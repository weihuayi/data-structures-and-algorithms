# Skill | 课程表达设计案例提取与重构

## 目标、对象和非目标

从真实的课程表达设计实践中发现值得理解的问题，恢复关键事实与设计判断，形成可追溯、可独立理解、可接受反例挑战的表达设计案例。支持后续教学、研究、技术写作和人机协作中的独立判断。

**案例不是 PR、页码、一次意见、线程摘要或“成功经验”的同义词。** 案例由具体任务情境中的表达设计问题、重要判断与实践演化确定身份。一个主案例可含若干修订事件；一个 PR 也可能涉及多个不相同的问题。不要求每个事件都有独立文件。

本 Skill 仅负责案例**发现（Discover）／重构（Reconstruct）／受控入库（Curate）**，不负责修改课件、实现算法、构建 HTML、测试程序、证明教学效果或制定团队正式知识规则。已有课件指南、知识整理 Prompt 和线程 Retro 不能替代本专项任务；本 Skill 也不能代替这些资产。最终事实确认、取舍和授权由人负责。

## 装配必要上下文

1. 先核验目标仓库、分支、提交与用户指定任务范围，读取根目录 `AGENTS.md`、`kb/README.md` 及 `kb/design_cases/README.md`。对读取的课程资料，按需查看相应 `course/AGENTS.md` 及课件设计卡；如果需要修改其它目录，再读取其作用域规则。
2. 以**具体表达问题**为检索主线，按需获取指定课件的 README、原始 `slides.py` 或历史文件版本、审阅记录、PR 与相关提交差异、CI、已有案例及用户提供的讨论／课堂记录。先查最相关来源，不无差别遍历整个仓库、其它仓库或历史记忆。
3. 历史转述、PR 描述、AI 总结和文件标题不等于已经取得原始事实。若无法获得源材料，注明缺失项及结论的可用范围；不能用外部常识或貌似合理的设计动机补写历史。
4. 课堂录音笔记及其自动转写须区分原始音频、衍生记录与教师或学生的直接学习证据。所见材料可包含受限信息：公开入库之前先检查授权和隐私边界，禁止外泄原件和学生个人资料。

## 选择工作模式与授权

- **发现**：用户要求识别、收集、筛选候选案例时，输出候选问题、情境、证据、身份/粒度、与既有案例的关系和未决事项；不默认写文件。
- **重构**：用户给出一个案例或明确问题时，基于可核验的记录恢复事实链和解释链，给出可独立阅读的候选案例；不默认提交。
- **入库**：用户明确授权创建或修订课程案例资产时，在授权范围内核验并修改 `kb/design_cases/` 及必要索引，检查公开性和 diff。**内容修改授权不等于 Git 操作或远程发布授权**：是否建立分支、创建提交、推送远程、创建 PR 或合并，分别根据用户已授权的具体动作及仓库 `AGENTS.md` 决定；仅获本地修改授权时不得自行执行这些后续动作。已明确授权的步骤可以连续执行，不必逐项重复确认。

用户明确目标和授权时直接执行相应模式，不设置无意义的重复确认。证据不足、当前无值得成案的问题、只能作为既有案例的修订事件、应先更新已有案例，均是正常结论，不强制输出新文件。遇到目标边界改变、关键事实无法核实或非公开材料缺少发布授权，暂停相应写入并报告，不扩大范围。

## 发现：先决定案例身份和粒度

1. 明确受众、教学或研究表达任务、原始版本及约束：当时要让谁理解什么？实际遇到什么表达困难？
2. 区分**可观察修订事实**、**设计者直接反馈**与**推断的认知困难**。改字、修断行不自动成案；但如果小修暴露跨表示、必要上下文、符号识别或约束机制，也可成为候选。
3. 判断是否存在有解释价值的问题机制、备选方案、取舍、转折、失败、反例及可迁移条件；不要求“最终改好”才算案例。
4. 比较已有 `kb/design_cases/`：相同问题的连续演化宜作为主案例与关联事件；只有在问题身份、独立解释价值或使用目标确有区别时才建议独立成案。不要按 PR、页码、讨论轮次、提交数量拆分。
5. 发现输出至少说明：候选问题、直接证据和定位、归属与粒度、价值依据、尚缺来源、建议继续重构／关联／暂存／不成案的理由。不得把模型自行产生的“洞见”直接记为发生过的事件。

## 重构：事实证据链与认知解释链

**事实证据链**：原始表达与任务 → 真实反馈 → 设计判断及时间先后 → 实际修订与版本 → 验证、后续实践及未测事项。对主要主张标识其证据类型：

- **版本事实**：源码、历史页面、确定提交、PR diff 可以证明的变更；
- **直接判断**：有出处的教师／参与者意见或已确认的设计选择；
- **间接转述**：自动转写、会议整理或他人摘要；注明其限制；
- **验证证据**：特定版本上的测试、浏览器检查、人工审阅与真实课堂结果，注明覆盖对象和条件；
- **事后分析／假设**：用于解释原因的候选机制、构造性方案及反例；
- **缺失或未验证**：原因不明、学生学习效果未知、来源无法取得、条件未满足等。

不要把当前 `main` 的课件冒充历史课堂使用版，不要伪造时间、失败原因、原始动机、团队共识或学生效果。关键来源尽量引用确定提交或实际 PR 差异；发现来源互相冲突时说明冲突。非公开证据可只保留获准公开的事实摘要、类型和访问限制，不创造伪链接。

**认知解释链**：真实设计问题 → 可能机制及证据 → 当时存在的选择和取舍 → 实施影响 → 适用条件、竞争解释与反例。把当时有记录的判断与现在提出的事后解释分开；若备选方案是为教学构造的，明确标为“构造性对照”，不能写成当时讨论过。

严格复核数学对象、符号、图示、状态、代码和数据的对应；数学正确性、课件可读性、自动检查和学生真正理解分别论证。不能把一次 PR 合并或 CI 通过作为教学有效性的证明。经验应允许被新课堂证据修订，且不能因新认识而回写历史。

## 输出、入库与质量控制

**发现结果**按问题列候选，说明身份、所据事实、证据不足处及优先复核的材料；可合理输出“不值得独立成案”。

**重构结果**服务未参与当时讨论的读者，按需包含：表达任务、具体问题、关键事实时间线、修订事件、竞争方案与理由、前后差异、证据边界、可迁移的候选认识、反例、后续验证问题及来源入口。只保留支持独立理解的必要材料，不强制复制 D014 章节数、事件数、全部对话或截图；教学性改写与原始历史须区分。

**入库结果**遵守现有 `kb/design_cases/` 职责，避免重复案例；按已有习惯使用清楚的文件名及索引。历史代码／课件仍由课程资产主维护。公开仓库不放原始录音、完整自动转写、学生身份、成绩、教师私人备注或未获授权材料。在授权范围内核对 Markdown/数学符号、可追溯链接、事实—解释分类、涉及文件和操作权限；只声明实际执行过的验证。按用户授权交付本地工作区修改、提交或 PR；只有已获远程发布授权并实际创建 PR 时，才交由教师在 PR 中审阅。未获合并授权不合并。

**定向压力测试**（依任务风险，不机械要求打分）：

1. 案例是否由实际表达问题而不是 PR、页面或模板决定？
2. 承重事实是否有实际取得的来源，且版本、时间和判断主体没有被改写？
3. 原始反馈、自动转写、AI 分析、实施与工程验证、学生学习效果是否被明确区分？
4. 机制解释是否保留成立条件、替代方案及可能反例，而非过度归纳？
5. 结果能否独立理解、不会泄露受限信息、不会越权写入或重复维护？

关键事实虚构、数学错误、未经授权公开或越权修改属于阻断问题；缺失学习效果可以如实标为未验证，不必阻断有价值的设计案例。
