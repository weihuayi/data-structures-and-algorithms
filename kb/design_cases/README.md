# Design Cases | 课程表达设计案例（试点）

本目录收集、解释课程实践中有依据的**表达设计案例**（Design Case）：重点保存表达任务、真实问题、关键判断、方案取舍、实际修订及证据边界，帮助后续教学、技术写作和评审中的独立判断。

**定位与边界**

- 本目录是课程仓 `kb/` 下的局部案例试点，不是对全课程、算海团队或其它仓库具有治理效力的正式表达规范。
- 案例的**事实来源**继续由相应课程源码、设计卡、历史提交、PR 和验证记录维护；此处选择必要证据并组织解释，不另建平行课件主源。
- 分别标明版本事实、原始反馈、事后机制分析、验证结果与尚未验证的学习效果。一个 PR 不自动等于一个案例；同一主案例可包含多个修订事件。
- 本仓公开：不上传课堂录音、自动转写原件、学生身份、学生发言细节或其它受限资料。非公开来源只说明其存在、范围、证据性质与局限，不制造公开可点击的伪链接。
- 案例可以供教学改编，但教学性重构或构造性对照必须明确标注，不能冒充实际历史版本。

## 维护原则

新案例应能让未参与原讨论的读者理解“任务是什么、问题在哪里、为什么这样改、实际改了什么、哪些得到验证、何时不适用”，并提供稳定版本来源。能在一份主案例中解释的关联事件，不机械拆分成多个文件。出现新课堂证据或反例时修订解释并注明新的证据，不改写原始历史。

后续是否需要跨课程索引、统一模板、教学变式或自动收集机制，依据此试点的使用与维护反馈判断，而非预先建设。
