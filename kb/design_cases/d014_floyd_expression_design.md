# Design Case | D014 Floyd 算法教学表达的连续重构

- **案例身份**：课程表达设计案例（试点），非正式团队规范，也不是算法教材或课件的替代主源。
- **理解对象**：如何在数学定义和程序计算均正确的条件下，组织更易识别的认知路径、状态表达、符号及验证。
- **实践对象**：D014《最短路径》，Floyd 部分第 30—34 页；相关 2026-11-04 课堂实践与 PR #14、#15、#16。
- **事实状态**：三个 PR 已合并；有课堂讲授及教师现场自述的表达困难证据；缺少针对修订后版本的学生学习效果证据。
- **写作约束**：事实时间线与事后设计解释分别呈现；录音笔记为 AI 辅助整理/转写，不能当作无误的音频复核或学生认知测量。

## 1. 这是什么问题？

课程首先讨论固定源点的 Dijkstra，随后希望回答“任意两点之间的最短路径怎样计算”。Floyd 部分需要让学生理解：为什么路径拼接引出受限内部顶点的阶段子问题，为什么能够逐轮只引入一个顶点，以及三重循环中的矩阵怎样从初始状态走向最终结果。

**核心设计张力**：数学描述可以正确，但概念引入缺乏动机、数学抽象与程序循环衔接不清、对象符号重载或投影实现问题，都可能使学习者难以识别承重关系。这些是设计问题及其可能机制，不自动等于已证明的学生学习障碍。

**案例边界**：本案聚焦 Floyd 教学表达的连续修订。Dijkstra 的首次课堂反馈、同一份录音笔记中涉及的 D015 拓扑排序，以及未来其它表达实践可作为关联来源或独立案例候选，不在此合并论述。

## 3. 哪些设计问题促成了修改？

### 事件 A：先出现抽象定义，还是先让问题需要它？

原版已能够描述受限最短路径，但学生为什么需要这种状态，缺少清晰的引入链。PR #14 在第 31 页增加具体路径拼接：已知 $A\to B\to E$ 长 10，而 $A\to B\to D\to E$ 长 7，促使读者思考拼接两段已知路径时，子结果何时足够可靠。

- **实施动作**：从目标与距离矩阵，经具体拼接进入受限子问题，再推导递推和循环。
- **事后候选解释**：在本教学目标中，具体冲突有助于赋予抽象阶段定义明确的问题职责。
- **限度**：这不是“所有数学概念都必须先举具体例子”的普遍规则；真实学习效果尚无独立测量。

### 事件 B：一般集合 $K$ 与固定循环 $k$ 怎样相互对应？

课堂使用的阶段定义，允许路径内部顶点来自集合 $K$；该数学定义成立，但程序并不枚举任意集合，而是固定顺序，每轮新增一个顶点。教师在课堂中明确提出“过去的顶点为什么可以不再检查”仍未讲清，随后修订将数学状态直接对应程序阶段。

- **实施动作**：固定顶点序列 $(v_0,\ldots,v_{n-1})$，以序列前 $k$ 个顶点为允许内部顶点，定义 $\boldsymbol{M}^{(k)}[i,j]$；第 $k$ 次外层循环处理顶点 `v_k`。
- **必要澄清**：“允许作为内部顶点”不代表路径必须按该顺序经过这些顶点；端点不受阶段前缀限制。
- **比较与边界**：集合 $K$ 适合描述更一般的受限路径问题；序列前缀则更直接对应此处的 Floyd 实现和教学目标。尚无证据证明它对所有受众更有效。

### 事件 C：初始化矩阵不只是一个表格

仅展示直接边构成的初始矩阵，尚不足以说明它与算法后续阶段的关系。PR #15 将第 30 页定义为状态起点 $D^{(0)}$，并解释更新同一程序矩阵、每轮结束获得下一阶段结果。

- **当前记号**：经过 PR #16 的符号修订，初始状态为 $\boldsymbol{M}^{(0)}$，最终为 $\boldsymbol{M}^{(n)}$。
- **事后候选解释**：要让学习者看到“矩阵表示的状态如何随算法发生变化”，而不是只看到单个静态数据表。

### 事件 D：矩阵和顶点可以都叫 $D$ 吗？

一度同时出现 $D^{(3)}[A,D]$：矩阵 $D$ 和顶点 $D$ 数学角色不同，但在相同教学片段中增加识别负担。讨论中曾比较重命名顶点、通过字体区分，以及另取矩阵符号等方案。

- **实际选择**：沿用团队提出的张量粗斜体约定，距离矩阵写作 $\boldsymbol{M}$，阶段为 $\boldsymbol{M}^{(k)}$，伪代码矩阵变量为 `M`；原始顶点 $A,B,C,D,E$ 不变。
- **适用条件**：这是在当前图、课件、团队表达约定和影响范围下的选择；不构成所有数学文本必须使用 `M` 的规则。

### 事件 E：写对了，能否被看清？

PR #15 的验证过程中，第 30 页曾在 1280×720 视口出现内容溢出，经文字压缩和重新检查后通过。说明“数学内容正确、源与 HTML 一致、投影可见、学生实际理解”属于不同层次的判断。

- **实际证据**：参见 [PR #15](https://github.com/weihuayi/data-structures-and-algorithms/pull/15) 的修订及关联 CI；[PR #16](https://github.com/weihuayi/data-structures-and-algorithms/pull/16) 继续通过符号与布局相关检查。
- **限度**：自动浏览器通过不等于任何设备、教室或课堂条件下都可读，也不等于学生理解了公式。

## 4. 核心数学对象与跨表示对应

采用当前课件记号。允许顶点顺序为 $v_0,\ldots,v_{n-1}$ 时，$\boldsymbol{M}^{(k)}[i,j]$ 表示从 `i` 到 `j` 的最短距离，路径**内部**顶点只允许来自此前的 $k$ 个顶点。没有可行路径则为无穷大。

```math
\boldsymbol{M}^{(k+1)}[i,j]
=\min\{\boldsymbol{M}^{(k)}[i,j],
        \boldsymbol{M}^{(k)}[i,v_k]+\boldsymbol{M}^{(k)}[v_k,j]\}.
```

在本讲非负权图中，按顺序新增顶点 $D$ 时，$A\to E$ 的阶段距离从 10 改进到 $4+3=7$；$C\to E$ 从 9 改进到 6。数学上的不同 $k$ 阶段由一份可变的程序矩阵 `M` 实现，完成一整轮外层 $k$ 后，对应 $\boldsymbol{M}^{(k+1)}$。内层循环途中可能是部分更新状态，不应硬说整个矩阵始终是同一完整阶段快照。

**明确的适用条件**：本课以非负权图解释阶段递推及原地更新；不在此通过单个教学案例证明所有含负权的变体或所有实现细节。

## 6. 可迁移的候选认识，而非通用处方

1. **数学正确性与表达适切性需分别判断。** 正确的集合定义也可能不足以支撑当前受众对程序阶段的理解。
2. **关键对象应跨表示保持可解释的对应。** 例如主例、数学状态、矩阵、代码循环和符号约定。
3. **抽象层次的选择依赖受众与任务。** 前缀序列不是一般性地优于集合；需要比较两者实际揭示的关系。
4. **工程验证与教学效果证据分开。** 自动测试给出限定范围内的可信依据，课堂是否促进理解需另外观察。
5. **保留真实设计中的修正和不确定性。** 本案例的认识是经过课前、课堂和课后反馈逐步发展的，不应改写成一开始就存在的完美方案。

## 7. 教学使用建议（尚未实测）

**独立研读**：先看 PR #14 之后、#15 之前的版本，判断集合 $K$ 的数学含义与循环 $k$ 的关系；再比较最终版本，说明优势、条件和代价。

**研讨活动**：让学习者在揭示实际修订之前分别提出“补充解释 $K$”“改用序列前缀”两种方案，比较数学正确性、认知路径、实现影响；最后核对 PR 和课堂反馈。

**迁移任务（构造性情境，非真实故障）**：某有限元教学课件同时展示网格顶点、局部/全局自由度、刚度矩阵索引与组装程序。分析其中可能的对象混淆和跨表示对应缺口；说明 D014 哪些判断能迁移，哪些修改不应直接照搬。

**观察指标候选**：学习者能否区分数学错误与表达缺口、给出有条件的方案取舍、辨明验证证据的边界，并在另一任务中独立进行符号与状态映射判断。这些指标尚未在本案例中经过教学效果研究检验。
