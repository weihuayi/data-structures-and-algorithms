## 一、矩阵目的

本矩阵不用于把教材章节重新排列成另一张内容表，而用于回答三个课程级问题：

1. 每个 Deck 主要承担什么**认知跨越**；
2. 已经建立的认知主线在后续哪些 Deck 中被**回收和深化**；
3. 每个 Deck 至少需要什么**学生侧可观察证据**，才能判断 Teaching Progression 是否正在转化为 Learner Progression。

因此，矩阵中的主线不是“每讲都必须覆盖的检查项”。如果一个 Deck 在所有主线上都被标记为主要任务，反而说明其认知焦点失去收敛。

## 三、标记规则

| 标记 | 含义 |
|---|---|
| **◎** | 当前 Deck 的主要认知跨越之一；设计应围绕它形成明确问题链与学生行为证据 |

| **—** | 当前没有必要显式承担，或现有依据不足以将其列入设计要求 |

Deck 状态采用：

| 状态 | 含义 |
|---|---|
| **R** | 当前仓库 `schedule.md` 有明确课堂运行记录 |
| **A** | Deck 资产已形成，但当前 `schedule.md` 未提供同等级明确运行记录 |
| **P** | 当前仅存在于课程设计方案的候选 Deck 地图中 |

状态只说明当前依据来源，不表示质量等级，也不表示学生已经形成相应理解。

## 六、每个 Deck 的最低学习证据接口

这一部分用于防止矩阵停留在教师设计层。  
v0.1 初始形成时，D001–D007 的条目优先继承当时 Deck 已有的“我怎样知道自己真的学会了”、作业与预测—运行—检查活动；D008–D020 当时作为后续设计建议。当前 D008–D013 的页面与独立任务已在本轮作设计层复核。下表仍是最低行为接口，不是已经取得的学生表现；D008 / D011 含共同约定展开前的建模，D009 / D010 / D013 主要为换输入后的机制应用，D012 为相近情境中的搜索应用。

| Deck | 最低学习证据接口 |
|---|---|
| **D001** | 给出一个新的小问题，学生能够指出对象、必要信息、关系、条件，并说明这些内容将怎样进入程序；运行代码前给出预测，运行后解释差异 |
| **D002** | 对有序配对扫描手工给出一次完整轨迹，并用不等式解释为什么一次判断可以排除一批候选；能够构造一个让错误策略失败的输入 |
| **D003** | 从地址公式解释 $O(1)$ 访问；预测一次插入需要移动多少元素；给出一个不适合顺序表示的场景并说明原因 |
| **D004** | 手工画出一次链表插入或删除的链接变化，解释修改顺序为什么重要；面对一个新场景在顺序表与链表之间做选择并给出依据 |
| **D005** | 对一个新行为需求判断应使用栈还是队列；手工推演循环队列状态，并解释判空、判满方案的设计取舍 |
| **D006** | 独立画出一个递归调用的压栈与退栈过程；指出基础情形、递推步骤和收敛方向；比较递归与迭代在空间上的差别 |
| **D007** | 手工推演 BF 与 KMP，指出 BF 丢掉了什么信息、KMP 重用了什么信息；构造一组使 BF 浪费明显的输入并解释原因 |
| **D008** | 面对一个未讲过的层次对象，学生能够识别根、父子、层次等关系，并比较至少两种可能表示及其操作影响 |
| **D009** | 在不给动画的情况下独立写出给定树的遍历序；改变访问顺序后解释结果为何变化；使用两种遍历序恢复一棵满足条件的二叉树 |
| **D010** | 给定字符频率独立构造 Huffman 树，计算带权路径长度，并与一个非最优方案比较；说明“结构优化”优化的究竟是什么代价 |
| **D011** | 把一个新的现实关系问题建模为图，明确顶点、边及边属性；在邻接矩阵与邻接表之间选择一种表示并说明依据 |
| **D012** | 对同一张图手工执行 DFS 与 BFS，解释栈/递归与队列分别承担什么作用；改变邻接访问顺序后预测遍历结果怎样变化 |
| **D013** | 手工执行一轮 MST 构造并说明为什么当前选择不会破坏目标结构；用并查集解释“当前哪些对象已经属于同一等价类” |
| **D014** | 手工完成若干轮松弛，解释当前距离估计怎样变化；说明一个距离何时可以被认为已经确定，并指出算法成立所依赖的条件 |
| **D015** | 把一个新的依赖/调度问题转成 DAG；完成拓扑排序或指出为什么不存在合法序；在小型项目网络中识别关键路径及其工程含义 |
| **D016** | 对同一数据分别使用顺序与折半查找，计算或比较 ASL；解释“序”为什么能够转化为查找收益，以及维护序本身需要付出什么 |
| **D017** | 执行 BST 插入/查找与至少一次 AVL 失衡修复；明确写出排序不变量和平衡不变量，并解释旋转如何恢复它们 |
| **D018** | 对给定键集合选择散列策略，手工推演冲突处理；比较不同装载因子或冲突策略下的时间、空间与实现代价 |
| **D019** | 手工推演一种插入排序与一种快速排序；指出过程中持续成立的局部性质；比较不同输入分布对算法行为的影响 |
| **D020** | 面对一个新的排序需求，在至少两种候选算法之间依据时间、空间、稳定性、数据规模与数据特征作出选择，并解释为什么没有脱离语境的“最好排序算法” |

## 七、跨 Deck 回收网络

### 7.1 问题—对象—表示主线

重点建立与回收位置：

```text
D001  建立：问题不是程序，先识别对象与信息
  ↓
D002  数据关系与组织
  ↓
D003  连续表示
  ↓
D004  抽象对象与物理表示分离
  ↓
D008  层次关系
  ↓
D011  一般关系
  ↓
D017/D018  同一“查找”任务的不同结构路线
```

其目标不是不断增加表示类型，而是逐步形成：

$$
\boxed{
\text{同一个计算对象可以有多种表示；
表示必须服务于操作需求和使用场景。}
}
$$

### 7.2 表示—能力—代价—选择主线

重点回收位置：

```text
D003  连续布局：访问收益 / 插删代价
D004  链式布局：访问代价 / 局部修改收益
D005  操作约束换取语义与可维护性
D008  双亲/孩子表示的上行下行代价；位置数组与链式选择
D010  保持关系的表示转换；给定前缀约束下优化 WPL
D011  邻接矩阵 vs 邻接表
D016  序的维护换查找收益
D017  平衡维护换稳定操作性能
D018  空间与冲突换平均查找性能
D019–D020  排序算法统一比较
```

这条主线最终应帮助学生形成：

$$
\boxed{
\text{没有脱离需求、数据特征和成本模型的“最好结构或算法”。}
}
$$

### 7.3 不变量候选主线

当前与计划中的关键验证位置：

```text
D003  连续表示不变量
D004  链接关系保持
D005  队列状态与受限接口
D008  修改父关系仍须单亲、无环、归根可达
D009  根与左右子树不重叠，规模递减
D012  首次发现即标记，只安排未发现顶点
D013  已选森林可行性与可扩展到最优解；DSU 分组语义
D014  最短路径逐步确认
D017  BST 顺序不变量 + AVL 平衡不变量
D019  已排序前缀 / partition
D020  Heap 等结构不变量
```

如果这些 Deck 均能让学生主动说出“变化中必须保持什么不变”，则“不变量”可以由候选纵向主线逐步升级为课程稳定深层主线。

### 7.4 信息利用候选主线

关键锚点与计划验证位置：

```text
D002  排序后的序信息可以批量排除候选
D007  已匹配信息不浪费
D008/D009  左右缺失位置与序列丢失的结构信息
D010  频率信息指导 Huffman 结构
D012  visited/parent/distance 积累搜索信息，避免重复安排
D013  权重与连通信息指导贪心选择
D014  当前距离估计通过松弛不断更新
D016  有序信息支持折半查找
D017  有序与平衡信息被显式维护
D018  映射信息直接预测位置
D019–D020  比较产生并积累顺序信息
```

需要持续追问：

> 当前结构或算法已经知道什么？  
> 新获得了什么信息？  
> 哪些未来计算因此可以被排除？

### 7.5 正确性候选主线

课程不应过早把所有算法强行形式化成统一证明模板，但可以逐渐回收四类问题：

```text
前置条件：当前方法在什么条件下成立？
保持性质：执行过程中什么不能被破坏？
进展：每一步究竟推进了什么？
终止：为什么过程一定会结束？
```

重点验证 Deck：

```text
D002  双索引为何不漏解
D003  操作后表示为何仍成立
D004  链接修改为何不断链
D006  递归为何终止
D007  KMP 为何无需主串回退
D009  不相交分解与规模递减保证树遍历
D010  交换与收缩支持最小合并
D012  标记、路径反证与有限工作保证图搜索
D013  割与交换支持安全选择；无环不等于最优
D014  最短路径何时可被确认
D017  旋转为何恢复结构而不破坏顺序
D019–D020  排序局部性质如何导向最终有序
```

## 八、Learning Progression 的阶段结构

从 D001–D020 的候选整体看，理论阶段可以暂时理解为五个认知段，而不是教材章节段。

### 阶段 A：进入计算世界

**D001–D002**

核心变化：

$$
\text{真实问题}
\rightarrow
\text{计算对象}
\rightarrow
\text{表示与组织}
\rightarrow
\text{算法可利用的信息}.
$$

### 阶段 B：表示、操作与抽象

**D003–D007**

核心变化：

$$
\text{Representation}
\rightarrow
\text{Operation}
\rightarrow
\text{Cost}
\rightarrow
\text{Abstraction}
\rightarrow
\text{Constraint}
\rightarrow
\text{Execution}
\rightarrow
\text{Information-aware Algorithm}.
$$

### 阶段 C：从线性关系进入复杂关系

**D008–D012**

核心变化：

$$
\text{Linear Relation}
\rightarrow
\text{Hierarchy}
\rightarrow
\text{General Relation}
\rightarrow
\text{Systematic Traversal}.
$$

这一阶段应重点回收 D005 的栈/队列和 D006 的递归。D010 同时桥接保持原关系的表示转换和改变树形的 WPL 优化；阶段表示侧重而非互斥分类。D012 区分图的表示、搜索辅助状态与待处理工作纪律，不把它们统称为同一种 frontier。

### 阶段 D：在关系结构上进行优化与决策

**D013–D015**

核心变化：

$$
\text{Graph Structure}
\rightarrow
\text{Invariant / Information}
\rightarrow
\text{Optimization}
\rightarrow
\text{Engineering Judgment}.
$$

这是检验“不变量、信息利用、正确性”三条候选主线能否真正贯通课程的关键区域。

### 阶段 E：主动建立和维护可搜索的结构

**D016–D020**

核心变化：

$$
\text{Search}
\rightarrow
\text{Order}
\rightarrow
\text{Maintained Structure}
\rightarrow
\text{Mapping}
\rightarrow
\text{Active Creation of Order}
\rightarrow
\text{Unified Choice}.
$$

这一阶段应完整回收 D002 的“数据组织如何改变搜索”，使课程形成一次大尺度闭环。

## 九、需要在后续设计中重点观察的结构风险

以下保留 v0.1 形成时提出的风险假设，不是对当前 D008–D013 的评审结论。本轮 D008–D013 已提供关系建模、过程正确与安全构造的设计反证，因而不能认定它们只剩定义与算法步骤；课堂是否照此实施、学生是否能解释仍未知，资产形成不表示风险已消除。

### 9.1 D008–D012 可能重新退化为“定义 + 遍历算法”

树与图是教材内容密集区。若 D008–D012 只追求定义、性质和手工算法覆盖，课程可能从 D001–D007 已建立的认知主线重新退回知识章节模式。

因此每个 Deck 应继续追问：

> 这个新的关系结构改变了我们表达什么、能做什么，以及算法如何利用这种关系？

### 9.2 D013–D015 是正确性与不变量主线的关键压力区

如果 MST、最短路径、拓扑排序最终只剩“背步骤、算结果”，则当前关于不变量、信息利用和正确性的深层主线假设基本失败。

这一组 Deck 应优先设计“为什么当前选择安全”“哪些信息已经确定”“什么性质始终保持”的学生行为证据。

### 9.3 D016–D020 必须形成对 D002 的大回收

D002 提出的是：

> 数据组织如何改变搜索？

D016–D020 应把这个早期问题发展为：

$$
\text{顺序}
\rightarrow
\text{树结构}
\rightarrow
\text{平衡维护}
\rightarrow
\text{映射}
\rightarrow
\text{主动排序}
\rightarrow
\text{统一选择}.
$$

如果这一回收成立，D002 不再只是早期案例，而成为贯穿理论阶段的长程问题主线。

### 9.4 迁移不能只停留在“挑战题”

如果陌生问题迁移始终只放在选做挑战中，则课程主干无法获得强 Learner Evidence。

至少应在若干关键节点设置低负担、非同型的必做迁移任务。候选节点包括：

- D004：顺序表 / 链表选择；
- D011：现实关系建模为图；
- D015：依赖关系转为调度问题；
- D018：BST 与 Hash 路线选择；
- D020：陌生排序场景综合选择。

## 十、课程级最小观测点建议

为了使本矩阵真正进入课程运行，而不是只作为设计图，可以在理论阶段设置少量跨 Deck 观测点。

| 观测点 | 建议位置 | 主要检查 |
|---|---|---|
| **Checkpoint A** | D004 后 | 能否区分对象与表示；能否根据操作需求比较顺序表与链表 |
| **Checkpoint B** | D007 后 | 能否解释“表示、信息、算法、代价”之间的关系；能否完成一次小型陌生问题迁移 |
| **Checkpoint C** | D012 后 | 能否把新关系建模为树/图，并选择表示与遍历方式 |
| **Checkpoint D** | D015 后 | 能否识别算法中的不变量、已知信息、成立条件和优化目标 |
| **Checkpoint E** | D020 后 | 能否面对陌生任务完成“对象 → 表示 → 算法 → 正确性 → 代价 → 选择 → 验证”的综合判断 |

这些观测点不等同于正式考试，也不要求新增高负担考核。其主要用途是为课程演化收集 Learner Evidence。

## 十一、D020 后希望形成的课程级能力闭环

如果本矩阵代表的 Learning Progression 最终成立，学生面对一个陌生问题时，应逐渐形成下面的判断循环：

```text
问题是什么？
    ↓
计算对象、信息和关系是什么？
    ↓
需要支持哪些操作？
    ↓
有哪些可能表示？
    ↓
这些表示分别创造什么能力、付出什么代价？
    ↓
什么性质必须保持？
    ↓
算法可以利用哪些已有信息？
    ↓
为什么算法成立？
    ↓
时间和空间代价是什么？
    ↓
当前语境下为什么选择这一方案？
    ↓
怎样预测、运行、测试、构造边界情况与反例？
    ↓
结果是否真正回答了原来的问题？
    ↓
把形成的判断迁移到新的问题
```

课程最终希望学生带走的不是一套固定算法清单，而是：

$$
\boxed{
\text{面对新的计算问题形成有依据、可验证、可比较的计算判断。}
}
$$
