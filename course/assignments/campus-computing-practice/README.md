- **程序语言**：C11

## 一、实践目的与范围

校园是大家每天学习和生活的真实环境。课程安排、校园道路以及各类服务活动中，都存在可以通过计算方法分析的问题。

本次实践以湘潭大学校园中的真实问题为背景，引导大家把现实需求转化为计算问题，运用本课程学习的数据结构与算法完成一个小规模、可验证的程序实践。

本次任务希望大家经历以下过程：

**现实问题 → 计算问题 → 数据表示 → 算法设计 → 程序实现 → 测试验证 → 结果解释。**

请注意本次实践的边界：

- 这是课程学习实践，不是要求大家参与智慧校园真实项目的工程交付。
- 题目中的数据均为教学构造数据，不是湘潭大学实际运行数据；不要求收集真实校园数据。
- 不要求接入学校现有系统，不要求建设完整的排课、导航或服务管理平台。
- 不要求开发网站、图形界面或数据库系统。
- 不组队。每位同学独立选择一个题目，提交一份报告。
- 程序在自己的电脑上使用 C11 环境编译、运行即可，不要求向公共 GitHub 仓库提交代码或创建 PR。

## 二、题目选择

三个题目任选其一。请根据自己的兴趣和对相关知识的理解选择，不需要同时完成多个题目。

### 题目 A：校园课表合理性分析

**现实问题**：一份课表中，相邻课程可能安排在不同教学地点。如果两节课之间的时间不足以完成移动，就会给学生带来不便，也可能形成教学区之间不必要的集中流动。

**本题范围**：只分析一名学生在同一天的一份小型课表，检查相邻课程之间的移动时间是否充足。不是求解全校自动排课问题，也不要求重新安排课程。

#### 基础课程数据

| 课程 | 开始时间 | 结束时间 | 地点 |
|---|---:|---:|---|
| C4 | 14:00 | 15:40 | A |
| C2 | 10:00 | 11:30 | B |
| C6 | 18:00 | 19:00 | B |
| C1 | 08:00 | 09:40 | A |
| C5 | 16:00 | 17:20 | B |
| C3 | 11:50 | 13:10 | C |

地点之间的预计移动时间（分钟）：

| 起点＼终点 | A | B | C |
|---|---:|---:|---:|
| A | 0 | 25 | 8 |
| B | 25 | 0 | 20 |
| C | 8 | 20 | 0 |

本题假设：课程属于同一名学生、同一天；课程时间没有重叠；地点之间的移动时间是对称的；同一地点之间移动时间为 0。

#### 必做任务

1. 识别课程记录及其属性，说明课程、时间和地点之间的关系。
2. 选择适当的数据结构保存课程记录。
3. 使用本课程学习过的一种排序算法，按课程开始时间排序；开始时间相同时，按课程编号升序排列。
4. 依次检查排序后相邻课程之间的时间间隔。计算可用移动时间、地点间所需移动时间，以及时间不足的分钟数。
5. 输出排序后的课程表，以及每一对相邻课程的检查结果。
6. 将 A、B 两地之间的移动时间从 25 分钟改为 20 分钟，重新计算并比较结果。
7. 测试空课表、只有一门课程等边界情况。
8. 自行设计至少一组测试输入，先预测结果，再运行程序核对并解释。

**需要回答**：哪些相邻课程之间存在移动时间不足？把 A、B 之间的移动时间减少后，结果发生了什么变化？

### 题目 B：校园道路网络与路径分析

**现实问题**：校园中的地点通过道路连接。给定出发地点和目标地点，需要判断两地是否连通，并寻找一条经过道路数量最少的路线。

#### 地点及编号

| 编号 | 地点 |
|---:|---|
| 0 | 宿舍区 |
| 1 | 教学楼 A |
| 2 | 图书馆 |
| 3 | 食堂 |
| 4 | 教学楼 B |
| 5 | 体育馆 |
| 6 | 暂未接入道路网络的区域 |

#### 道路连接关系

| 道路 | 起点 | 终点 |
|---|---:|---:|
| E1 | 0 | 1 |
| E2 | 0 | 2 |
| E3 | 1 | 4 |
| E4 | 2 | 3 |
| E5 | 3 | 5 |
| E6 | 4 | 5 |
| E7 | 1 | 2 |

本题假设：道路是双向的；每条道路都视为一条边，不考虑道路长度、坡度和通行时间；图是无权无向简单图；顶点编号为 0–6。邻接顶点按编号从小到大检查，以便结果可复核。

#### 必做任务

1. 将道路网络抽象为图，明确顶点、边及其含义。
2. 选择邻接矩阵或邻接表表示图，并说明选择理由。
3. 使用广度优先搜索（BFS），判断从地点 0 到地点 5 是否可达。
4. 如果可达，输出一条经过道路数量最少的路径及其边数；如果不可达，明确报告不可达。
5. 暂时关闭道路 E3（即删除顶点 1 与顶点 4 之间的边），重新计算地点 0 到地点 5 的路径并比较。
6. 检查地点 0 到地点 6 不可达的情况。
7. 自行设计至少一组测试输入，先预测结果，再运行程序核对并解释。

**需要回答**：为什么 BFS 能在本题条件下找到经过边数最少的路径？关闭 E3 后，路线怎样变化？

注意：本题中的“最少”指经过的道路数量最少，不代表实际地理距离最短或通行时间最短。多条最少边数路径都正确；若按编号升序扫描邻接顶点，可以得到确定的示例路径。本题不要求实现 Dijkstra 等带权最短路径算法。

### 题目 C：校园服务请求与等待时间分析

**现实问题**：快递、外卖或其他校园服务活动中，多个请求可能先后到达并等待处理。服务时间的变化可能影响后续请求的等待时间。

**计算任务**：建立一个只有一个服务窗口的简化模型，模拟请求处理过程，计算每个请求的等待时间及整体等待情况。

#### 基础请求数据

| 请求 | 到达时间（分钟） | 服务时间（分钟） |
|---|---:|---:|
| R4 | 4 | 1 |
| R2 | 1 | 2 |
| R6 | 10 | 1 |
| R1 | 0 | 3 |
| R5 | 10 | 2 |
| R3 | 1 | 4 |

本题假设：只有一个服务窗口；服务过程不可中断；按先到先服务（FIFO）处理；到达时间相同时，按请求编号升序处理；服务窗口空闲且没有等待请求时，等待下一请求到达。所有时间均为非负整数，服务时间为正整数。

#### 必做任务

1. 分析请求对象及其到达时间、服务时间等属性。
2. 按到达时间和请求编号组织请求，使用 FIFO 队列（可以用数组实现）管理等待请求。
3. 模拟服务过程，输出每个请求的开始服务时间、完成时间和等待时间。
4. 计算所有请求的平均等待时间和最大等待时间。
5. 将 R3 的服务时间从 4 分钟改为 1 分钟，重新模拟并比较结果。
6. 测试空请求集合、单个延迟到达请求等边界情况。
7. 自行设计至少一组测试输入，先预测结果，再运行程序核对并解释。

**需要回答**：为什么请求需要按照 FIFO 规则处理？一个请求服务时间缩短后，哪些后续请求的等待时间发生了变化？

## 三、统一报告要求

每位同学只提交一份个人综合计算实践报告。报告不设硬性字数和页数要求，以内容准确、过程清楚、结果可复核为准。

报告应包含以下七部分：

1. **问题理解**：说明现实背景、计算目标、问题边界和简化假设。明确哪些现实因素没有纳入模型。
2. **计算对象与数据表示**：说明计算对象、属性、关系、输入输出，以及所选数据结构和选择理由。
3. **算法设计**：说明算法的基本思想和步骤；至少给出一个关键过程的手工推演；分析主要时间和空间代价。
4. **程序实现**：使用 C11 实现基础任务，说明主要函数、关键数据和程序运行方法。完整源代码放在报告附录中。
5. **测试与验证**：包含基础数据测试、题目规定的变化测试、边界测试和至少一组自主设计的测试。每组测试应保留预测、实际运行结果及差异解释。
6. **结果解释与局限**：解释计算结果能说明什么、不能说明什么，以及模型和算法的适用条件。
7. **学习反思**：说明自己遇到的主要困难、获得的帮助、如何核对，以及对数据结构与算法的理解有什么变化。

**先预测，再运行，再解释。** 预测与实测一致，只能说明该组输入下的结果相符，不能单独证明算法对所有输入都正确。请结合边界情况、算法机制和适用条件说明验证依据。

## 五、AI 与其他学习资源的使用

可以使用教材、网络资料、AI、教师和同学交流来帮助学习，但必须保持独立思考和核对责任：

- 先独立理解和尝试，再按需要寻求帮助。
- 不直接复制未经检查的算法和代码。
- 对 AI 生成或修改的程序，必须实际编译、运行和验证。
- 能够解释自己采用的数据结构、算法机制和关键计算过程。
- 如实说明获得了哪些帮助，以及如何检查和确认结果；没有使用 AI 也如实说明，不必为了记录而使用。

报告末尾用 3–5 行记录初始思路、主要困难、获得的帮助及核对方式。该记录与程序的预测—实测对照职责不同，不能相互替代。

## 八、希望通过这次实践获得什么？

学习数据结构与算法，不只是记住定义、公式和程序。更重要的是，面对一个现实问题时，能够主动判断：问题是什么，需要处理哪些信息，怎样表示对象及其关系，可以采用什么计算方法，怎样实现并验证自己的想法，以及计算结果能够支持什么判断。

校园是我们每天生活的地方。我们不仅可以适应周围的环境，也可以通过自己的学习、思考和实践，参与创造更好的环境。

**希望大家通过这次实践，第一次比较完整地体验：自己所学的知识，能够帮助自己理解和解决身边的问题。**
