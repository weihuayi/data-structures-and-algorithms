# 作业规范｜面向学生

**每次课的正式作业由对应课件的课后作业页布置**，具体题目及要求以该页为准。本文件维护共同要求，不另建一套题目。A、B 为正式必做部分；明确标为自学、挑战或选做的任务不提交。教师或助教可以按周集中收取多次课作业，并通知提交入口与截止时间；每周累计任务量原则上以 1–2 小时为目标，若涉及多讲须核对总负担。

## 一、作业内容和必要产出

- **A．书本习题**：完成课件中明确列出的章、题号。选择题附一句理由；应用、计算题保留关键推演；算法设计题写出思路与关键步骤。
- **B．扩展作业／程序实践**：按本讲给定输入和要求完成预测、推演、代码补全或实验。涉及代码时，先写预测，再实际运行，记录实测结果及是否一致、为什么。
- **过程记录**：每份正式作业末尾用 **3–5 行**简述初始思路、遇到的困难、获得的帮助及如何核对。没有使用 AI 就如实说明未使用，不必为了记录而使用 AI。过程记录与程序预测—实测对照职责不同，不可相互代替。
- **提交代码的条件**：只观察或修改输入时，提供题目所要求的预测、结果和解释；亲自补全、修改或实现代码时，另附足以核对的关键代码片段或对应源文件及必要测试说明。**运行截图不默认强制要求**，清楚的输出文本或表格也可作为证据。

## 二、程序在哪里运行？

可从课程仓库**下载、复制或克隆**所需的 C 源文件，在**学生自己电脑的本地目录**使用适当的 C11 编译器或 IDE 编译运行，并保留程序实际需要的其它文件。课件中的 `code/xxx.c` 是本讲目录下的相对源码路径；`/tmp/d0xx` 是 Linux 示例中的**本地可执行文件路径**。参考命令注明工作目录，只是为了解析相对路径，**不代表必须在 Git 仓库执行**。

**普通作业不要求向公共 GitHub 仓库 push 源码、运行结果或创建 PR。** 只有明确要求 Git 协作的独立任务才需要这类操作。可以在自己的电脑上采用等效编译、运行方式，但必须真正运行并能解释结果。

## 三、AI 使用

先独立尝试，再按需要借助 AI、教师或同学；不要直接誊抄未经检查的 AI 输出。记录自己如何核对输入、代码、执行和解释。未使用 AI 不影响完成作业。

## 四、提交渠道与自检

通过**飞书云文档**完成作业，把可查看的文档链接提交到助教通知的收集表；不将个人身份、成绩或私有学习记录发布到公共仓库。

- **文档命名**：通常为 `学号-姓名-D016` 一类格式；如果集中收取多讲，按该次通知使用相应的 Deck 编号组合。
- **文档结构**：A 的题目与解答／B 的预测、必要代码、实测与解释／最后 3–5 行过程记录。没有代码任务不必填空白的“代码结果”栏目。
- **提交前自检**：A/B 必做内容齐全；选做已区分；需要的预测、实测及解释在场；要求运行的代码已真实运行；飞书分享权限和链接正确。

实际发布要求若有调整，应由教师或助教明确告知，不追溯增加此前未被通知的必做任务。A 部分为考试复习的重要基础，具体考试范围仍以课程正式通知为准。
