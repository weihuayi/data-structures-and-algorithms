# HTML 课件制作与修订约定

继承[课程约定](../AGENTS.md)。完整共性见[课程课件共性约定](../../docs/design/deck-contract.md)，方法见[修订指南](../../docs/design/deck-revision-guide.md)，实现见[工具说明](../../tools/deck/README.md)。修改共享实现时另读 [tools/deck/AGENTS.md](../../tools/deck/AGENTS.md)。

## 开始与制作

1. 核对本讲 README、源与生成物，明确本次问题、页面职责、任务要求的结果及验收方式。新讲先形成认知路径与边界；小修只记录必要影响。
2. 课件目录使用 `dNNN-slug/`。维护 README 设计卡、`slides.py` 主源、受控生成的 `index.html`，按需维护强绑定的 `code/` C11 演示。代码以 `gcc -std=c11 -Wall -Wextra` 编译运行，课堂遵循先预测、再运行、再检查。不手改生成 HTML，不新增并列 handout 主源。
3. 新课件复用 `CourseDeck`、`Section`、任务区等公共能力，保留三元组接口。页面 ID 稳定，认知责任明确；部分数、页数及交互粒度由学习任务决定，不能由页数换算授课时间。
4. 大纲和起始页从相同部分声明生成。默认大纲采用有序导航，突出主题与主问题；起始页以一个主标题表达完整阶段。默认形式的偏离在设计卡或 PR 简述教学理由。
5. 任务所在处保留必要输入。构造、补全、转换任务默认呈现完成后的结构或产物，并解释理由；检查答案确实完成所问任务。提示与答案按教学需要收起，避免默认标题或图注提前泄漏结果。
6. 教材定义完整、术语准确并明确锚定；案例驱动的问题链按实际认知依赖组织。交互状态与完成标记必须具有准确含义；具体边界遵循共同约定。
7. 教师注记按需要选用，投影默认收起，打印隐藏正文；不借折叠堆积不必要内容。公开与私有边界遵循根约定。
8. 构建后同步 README 中派生职责表；新讲登记到课件目录。实际发生授课时才更新对应 offering。

## 完成验收：检查、修订、复查

- 使用 `python3 tools/deck/verify.py --base <基线> --output <新目录>` 运行按影响范围的系统检查。新课件检查全部页面与受支持操作；局部修改审阅关联页面；共享组件覆盖全部采用者与受影响旧课件。
- 沿六方面共性进行 AI 内容自审，并检查最终浏览器页面的默认、展开和步骤状态；核对任务与答案产物、重复信息、输入在场、图文对应及可读性。机器通过后仍须执行。
- 对发现的问题记录稳定页面 ID、影响、处置和复查证据。正确性、必要输入、错误答案、不可读主内容及本轮新增回归须先修复；历史问题与覆盖缺口单列，不改写机器原始结果。
- 用工具说明中的 `review.py` 记录并检查交付审阅。最终记录绑定当前源码与共享依赖，覆盖适用六方面及受影响对象；修改后使旧记录失效并补做必要复查。
- 提交 PR 前必须得到有效交付记录，或明确报告尚未完成及原因，不以“测试通过”代替完成验收。AI 自审、教师审阅和课堂证据分别标识；普通制作任务终点是可供教师审阅的成果，无需等待课堂效果证据。
