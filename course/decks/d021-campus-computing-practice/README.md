# D021｜从校园生活到计算问题

> 状态：合并后质量复审修订候选；正式构建、机器检查、最终视觉审阅与教师确认分别记录，不记录未发生的授课或学习达成。

## 教学中心与范围

从熟悉的湘潭大学校园生活出发，引导学生观察、讨论、识别关系和提出问题，再抽象出可计算的任务，回收 D001–D020 的专业认识。D021 不承担完整期末题目求解或实际智慧校园项目交付。D022 使用不同教学数据示范从明确问题到可验证程序。

## 目标与最低学习证据

| 目标 | 课堂可观察行为 | 证据边界 |
| --- | --- | --- |
| G1 问题意识 | 描述校园真实经历，区分观察、假设与待核验解释 | 自愿发言或独立纸笔思考；不是全班掌握证据 |
| G2 系统联系 | 解释活动、空间、需求、通行条件的一条关系 | 不把示意当作真实因果验证 |
| G3 计算抽象 | 在构造座位案例明确输入、输出、条件，独立核对 | 近情境小任务，不声称已获独立迁移能力 |
| G4 知识整合 | 说明对象、表示、算法、条件和代价的一项关联 | 专项掌握仍需后续复习 |
| G5 实践认识 | 理解期末三题任选一、报告与验证要求 | 本讲不要求当场选题、提交方案或报告 |

## 设计依据与课堂路径

- [课程 Learning Progression](../../data_structures_algorithms_learning_progression.md)、[D001–D020 Matrix](../../data_structures_algorithms_D001_D020_learning_progression_matrix.md)、[Deck Contract](../../../docs/design/deck-contract.md)；D001 问题到表示、D020 条件化选择是两端接口。
- [CMU Eberly Center learning principles](https://www.cmu.edu/teaching/principles/learning.html)：激活先修、整合知识、目标导向练习与反馈；[How People Learn II](https://www.nationalacademies.org/read/24783/chapter/7)：提取练习与知识整合的研究依据。设计参考不等于本班效果证据。
- 五个认知部分见 [Storyboard](storyboard.md)。以认知完整性、接续性为首要目标；时间为课堂实际约束而非硬指标。校园讨论、计算抽象、知识回收后均可自然暂停。适当保留现场开放讨论；不需要分组或正式提交短任务。
- 真实校园素材尚未核验，使用学生自身观察和明确标注的概念图。教师可现场展示经授权素材，不声称具体系统状态或量化效果。

## 工程与验收

使用现行 CourseDeck、Section、task_workspace，统一封面、公共导航、版式及结尾；本讲 `lesson.css` 局部样式继承 D018–D020 封面与结尾视觉语言，等高并列块，不改共享视觉组件。无公式故不加载 KaTeX；无新 JS、无新增第三方依赖。两个独立核对任务使用公共工作区。 `slides.py` 是页面主源；`index.html` 为受控派生物，正式以 `python3 tools/deck/build.py D021` 生成。构建后运行 `python3 tools/deck/verify.py --base origin/main --output /tmp/d021-review`（本地分支需以正确基线替换），覆盖页面、交互、作业检查、视觉、六方面审阅记录与复查。本轮质量复审见 [quality-review.md](quality-review.md)；定向 CI 对构建前后差异、全页与全部支持操作分别检查，仍需实际运行结果与视觉复审记录。
