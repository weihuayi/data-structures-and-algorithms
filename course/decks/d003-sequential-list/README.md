# D003｜顺序表：表示与访问机制

## 本质关系

顺序表示 = 把逻辑相邻映射为物理相邻。地址公式 LOC(aᵢ) = base + (i−1)×L 给出与位置无关的 O(1) 访问；插入、删除中的搬运正是在维护表示不变量"第 i 个元素恒在 base+(i−1)×L"。访问 O(1) 与增删 O(n) 的对照就是顺序表示的适用边界：强项与边界来自同一个原因——连续布局。

## 接口方向

- **教材锚点**：《数据结构（C语言版）（第3版）》2.1–2.4——线性表定义、顺序表示与实现、抽象数据类型操作集合（InitList、Length、GetElem、LocateElem、ListInsert、ListDelete 等）。
- **数学接口**：数组是数学向量的直接表示（第 i 个分量 ↔ x[i]）；科学计算的一切（矩阵、BLAS、有限元）都建在连续数组上。
- **生活连接**：快递柜——凭柜号直接开柜，不用挨个敲门；柜号 ↔ 地址。
- **实践种子**：大规模数据存取；连续内存与缓存友好性（教师注记中点到）。
- **回收 D002**：逻辑结构 vs 存储结构、大 O、"先预测、再运行、再检查"的课堂口径。
- **本课首次引入**：内存模型——内存是巨大的字节数组、地址是字节编号（指针 = 地址的完整表述在 D004 建立）。

## 主要教学目标

- 能写出地址公式并解释每一项，理解访问代价与位置无关的原因；
- 能预测并验证一次插入、删除的搬运次数，理解 O(1) 与 O(n) 对照即适用边界；
- 认识表示不变量，初步建立"在变化中找不变"的正确性判断方法；
- 能把顺序表与 ADT 操作集合、多项式案例建立对应。

## 主要问题

- 数据住进内存，住成什么样？放在哪？怎么找、怎么改？
- 知道第几个，怎样算出它住在哪？
- 插到第 i 位，要搬几次？为什么愿意付搬运的代价？
- 数组住满了怎么办？稀疏多项式该住哪？

## 主要案例

快递柜（柜号 ↔ 地址）、按学号插入新同学的名单（手工推演搬运次数）、一元多项式的系数数组（下标即次数），稀疏多项式作为留问收口。
