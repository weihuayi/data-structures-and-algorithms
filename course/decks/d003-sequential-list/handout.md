# D003 顺序表：表示与访问机制｜学生讲义

## 从"找得快"到"变得起"

上次课用排序和双索引扫描让商品配对搜得更快。但排好序的清单面对的是一个一直在变的世界：新商品上架，旧商品下架。数据组织不仅要"找得快"，还要"变得起"。本次课沿三个问题展开：数据住进内存，住成什么样？放在哪？怎么找、怎么改？

## 内存与地址

回收 D002 的内存模型：内存是一个巨大的字节数组，每个字节有一个编号，叫做**地址**。给出一个地址，就能直接读出那个字节，不需要从头找起。

生活中的快递柜是同一机制：挨家敲门找包裹，只能一户一户问；快递柜凭柜号直接开柜，代价与柜子总数无关。柜号之于格子，正如地址之于字节。

## 线性表与顺序表示

名单、成绩单、每日股价，元素之间只有"前后相继"的关系，抽象出来就是**线性表**：$n$ 个数据元素的有限序列。回收 D002：排序前后的商品清单都是线性结构——序是逻辑关系，与住在哪里无关。

一个自然的选择是：逻辑上相邻，物理上也相邻。把线性表的序关系直接映射为内存中的连续布局，第 1 个元素之后紧接着第 2 个，依次排下去。这就是顺序存储表示，这样实现的线性表称为**顺序表**。

## 地址公式

连续布局带来的问题是：知道第几个，怎样算出它住在哪？答案是地址公式：

$$\mathrm{LOC}(a_i) = base + (i-1)\times L$$

- $base$：第 1 个元素的地址（基址）；
- $L$：每个元素占用的字节数；
- $i-1$：第 $i$ 个元素前面隔着 $i-1$ 个元素。

每一项都有明确的来源：从基址出发，跨过 $i-1$ 个元素，每个元素占 $L$ 字节。公式只做一次乘法、一次加法，**访问代价与 $i$ 无关**。

C 编译器正是按这个公式工作的。`int a[8];` 中，数组名 `a` 记录首元素的地址，`sizeof(int)` 给出 $L$，`a[i]` 就是地址 $base + i\times L$ 处的内容。C 的下标从 0 开始：第 1 个元素是 `a[0]`，地址即 $base$，对应公式中 $i-1=0$。

[`code/addr_demo.c`](code/addr_demo.c) 打印数组每个元素的真实地址。先预测：若 int 占 4 字节，`&a[3]` 与 `&a[0]` 相差多少字节？由公式，相差 $3\times L=12$ 字节。运行程序检查：相邻元素地址差恰为 `sizeof(int)`，`&a[3]` 的偏移恰为 12 字节。先预测、再运行、再检查。

## 访问：O(1) 意味着什么

100 件商品取第 57 件，一次地址计算；100 万件商品取第 57 万件，仍然一次地址计算。访问代价不随规模增长，这就是 $O(1)$——顺序表示用连续布局换来的回报。回收 D002 的大 O：它不关心具体几次，只关心代价随规模怎样增长。

## 插入与删除：搬运的代价

新任务的主角从"找"变成"改"：转专业的新同学来了，要按学号插进名单。8 人名单 [101, 103, 105, 107, 109, 111, 113, 115]，新同学学号 104，应插到第 3 位。先自己答：要搬动几个人？

手工推演：从 115 开始，105 到 115 共 6 人依次后移一位，腾出第 3 个位置，再放入 104。插到第 $i$ 位，要后移 $n-i+1$ 个元素；从最后一个人开始搬，是为了不覆盖还没搬走的元素。

删除是搬运的另一面：删除第 $i$ 位，要前移 $n-i$ 个元素补上空位。无论插入还是删除，平均要搬约一半元素，最坏全搬，时间复杂度都是 $O(n)$。

[`code/seqlist.c`](code/seqlist.c) 实现了固定容量的顺序表，插入、删除时打印实际搬运次数，可以逐条核对上面的预测。

### 代价对照

| 操作 | 代价 | 原因 |
| --- | --- | --- |
| 按位置访问 | $O(1)$ | 地址公式直接定位 |
| 插入 | $O(n)$ | 为保持连续，整体后移腾位 |
| 删除 | $O(n)$ | 为保持连续，整体前移补位 |

这张对照表就是顺序表示的适用边界：强项与边界来自同一个原因——连续布局。知道什么时候不该用它，和知道它是什么同样重要。

### 为什么还愿意付搬运的代价

很多场景里访问远远多于增删：成绩表一学期录入几次、查询成百上千次；每日股价每天新增一条、分析时反复读取；向量运算中数据固定、反复按位置参与计算。呼应 D002 的主题：没有最好的表示，只有适合任务的表示。

## 数组与数学向量

数组是数学向量的直接表示：向量 $x$ 的第 $i$ 个分量就是 `x[i]`，下标即分量编号。科学计算的一切——矩阵、BLAS 基础线性代数库、有限元——都建在连续数组上。数学对象找到对的计算表示，整套计算工具就都能用上。

## 容量：定长的代价

`int a[8];` 住满了怎么办？数组定长，第 9 个元素来了住不下。**扩容** = 重新分配一块更大的连续空间，再把所有元素整体搬过去。定长是顺序表示的第二个代价。`code/seqlist.c` 演示了表满时插入被拒绝并打印提示。

## 回到教材：线性表的抽象数据类型

教材中的定义：

> 线性表是 n 个具有相同特性的数据元素的有限序列。

教材 2.2 节给出线性表的抽象数据类型，基本操作包括：

| 操作 | 作用 |
| --- | --- |
| InitList / Length | 构造空表 / 求表长 |
| GetElem / LocateElem | 按位置取元素 / 按值找位置 |
| ListInsert / ListDelete | 在指定位置插入 / 删除元素 |

ADT 规定"能做什么、条件与结果是什么"，不规定"怎样存"。本讲的顺序表是这些操作的一种实现；同一种 ADT 还可以有其他实现，操作的代价也可能不同。

## 一元多项式：下标即次数

$P(x) = 3x^2 + 2x + 1$ 怎样住进数组？让系数住数组，下标即次数：

| 下标（次数） | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 系数 | 1 | 2 | 3 |

这是地址公式的又一个化身：知道次数，一次算出系数的住处。

### 稀疏多项式的委屈

$x^{10000} + 2x + 1$ 也要 10001 个位置吗？按"下标即次数"，这个多项式要开一个 10001 个位置的数组，其中 9999 个位置住着 0。绝大多数位置空着，只为保住"下标即次数"——顺序表示在这里输了。有没有一种表示，只给真正存在的项安排住处？下次课回答。

## 表示不变量

无论怎么插入、删除，顺序表都维护着一条不变量：

$$\text{第 } i \text{ 个元素恒在 } base + (i-1)\times L$$

每一次搬运都不是麻烦，而是为了让这个不变量重新成立——正是它保证了访问的 $O(1)$。在变化中找不变的东西，是判断数据结构正确性的通用方法；检查插入、删除代码的标准不是"跑通了"，而是"不变量是否仍成立"。

## 三个情境，同一套机制

| 情境 | 数学 | C |
| --- | --- | --- |
| 快递柜：凭柜号直接开柜 | 序关系映射为连续布局 | 数组 |
| 名单：按学号插入新同学 | $\mathrm{LOC}(a_i) = base + (i-1)\times L$ | 下标与 sizeof |
| 多项式：下标即次数 | 第 $i$ 项恒在其位的映射 | `coef[i]` 直接读写 |
