第一部分 · 把依赖关系说清楚

合法顺序为什么可能不唯一？

教材定义（概述）
拓扑排序（Topological Sorting）将全部顶点排成一个序列；每条弧的起点都排在终点之前。

A B C E D F

B A E D C F

这两种都满足所有依赖。

A 与 B 无先后约束；序列中排在前面，不等于现实中必须串行执行。

第一部分 · 把依赖关系说清楚

互相等待，与当前依赖模型冲突在哪里？

A 必须等 E 完成才能开始；E 又必须等 A 完成。

这种一次性、先完成再开始的依赖无法启动。

无环的有向图称为有向无环图（Directed Acyclic Graph，DAG）。

反馈与反复迭代需要另建模型，不由此断言现实中的环都不合理。

第二部分 · 产生合法推进顺序

为什么选择零入度顶点不会破坏顺序？

轮次开始时，已输出顶点的出边都已处理。

若某未输出顶点的剩余入度为 0，它的全部前驱都已在前面。

把它放在下一位，不会把任何前驱放到它后面。

栈或队列决定多个合法候选间的选择次序；合法性来自零入度条件。

第二部分 · 产生合法推进顺序

没有候选，又没排完，为什么说明有环？

剩余顶点都有剩余前驱。

沿前驱不断回溯，有限个顶点中必有重复，因此存在环。

本例只有 A、E 在环上；C、D、F 是受阻的后续活动。

判据：候选为空且输出数小于顶点数；不是“剩余顶点全部构成一个环”。

怎样核对别人给出的顺序？

序列② A B D E C F

哪一个合法？请指出具体检查依据。

核对答案与理由

① 合法；② 把 D 排在 E 前，违反 E→D。

先查每个顶点恰好出现一次，再对每条弧检查起点位置小于终点位置。

怎样把排位和更新写进程序？

u = stack[--size];
r->order[r->count++] = u;
for (e = g->head[u]; e != -1;
     e = g->edge[e].next) {
    v = g->edge[e].v;
    if (--r->degree[v] == 0)
        stack[size++] = v;
}

第四部分 · 时间余量与关键活动

几轮计算，为什么仍是线性工作量？

阶段在邻接表上完成的工作
拓扑排序初始化全部入度；每个顶点进出候选一次，每条弧解除一次
正向与反向按两个方向各扫描全部顶点和全部活动
活动判定每条活动计算 e、l、余量，并判定是否关键

总时间 \(O(n+m)\)；图存储 \(O(n+m)\)，辅助数组与栈 \(O(n)\)。

n 为当前图的顶点数，m 为弧数。以上针对已校验邻接表上的算法；输入检查、追踪快照与输出另计。枚举全部关键路径可能有指数规模。
