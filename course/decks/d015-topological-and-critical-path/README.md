# D015｜拓扑排序与关键路径：依赖关系怎样决定顺序与工期？

## 设计卡与内容边界

2026-11-01 依据三轮交互讨论与压力测试制作 HTML 初稿。主线：依赖约束 → 合法顺序 → 最早工期 → 时间余量与关键活动。四部分、33 页为初稿表达结果；页数服务对象在场、逐步推理和独立作答，活动预算不按页数换算。尚无本讲课堂运行、实际用时或学生达成证据。

2026-11-04 定向修订：保持四部分与原主例，新增两页数据表示与状态认知桥接，目标为 **35 页**；统一题目侧的必要输入、事件及活动时间数组的索引、数学公式与程序字段的对应。本讲课堂时间和学习效果仍待实践核验。

主要认知变化：从按既定步骤处理图，转向说明依赖条件怎样决定合法选择、信息处理次序和时间约束。

- 必须理解：AOV 与 AOE 对象含义；剩余入度、零入度选择、安全性和停滞判环；正向 max 与反向 min；事件时间、活动开始时间、总时差和关键路径的区别；多关键路径及模型条件。
- 默认实现：出邻接表、栈式拓扑排序、明确源汇及 topo 数组、两向时间计算；只输出关键活动和一条代表路径。
- 主线外：DFS 版拓扑算法、任意 AOV/AOE 转换与复杂虚活动构造、资源受限排程、随机工期、完整项目管理系统。教师说明可以解释零时长虚弧；它仍是存在的依赖，不能当作无边。

模型条件：活动持续时间固定且非负，依赖为先完成再开始，允许并行且资源不形成额外限制。AOE 为一源一汇 DAG，所有事件属于完整项目网络；源、汇是显式身份，不由编号大小推定。多源/多汇需先显式规范化，不在普通计算中悄悄忽略。最迟时间统一以不延长最早工期为准：`vl[sink]=ve[sink]=T`。

## 状态和工程约定

- 原图不变。拓扑步骤区分 output/read/release/boundary/done/blocked；每个微状态的入度等于尚未解除的入边数。“来自未输出前驱的入边数”仅在轮次边界解释。
- 正向在前驱全部传播后标记事件值确定；轮中未完整的汇总值是下界。反向待全部后继期限汇总后才标记确定。“—”表示尚未汇总，不是 0。
- 三个播放器使用公共上一步/下一步/重置；图、输入记录与相应数值同屏。红粗实线表示当前读取的弧，状态同时用文字和表格解释，不只靠颜色。
- 任务条件、图和必要值在展开答案后保持可见；答案默认收起，打印保留问题并隐藏答案，只打印播放器当前状态。连续阅读不是所有步骤的独立静态讲义。
- 算法对已校验邻接表的核心计算为 O(n+m)，辅助空间 O(n)。追踪快照、输入合法性检查和输出开销另计；不把枚举全部关键路径纳入线性承诺。
- Python 生成器接受小型简单 DAG；C 演示至多 32 顶点、256 弧，整数时长 0–1000000，保证求和安全。C 图输入检查与邻接表构造先于核心计算。
- 计算与 HTML 渲染分离；以独立路径枚举作为小图 oracle，再与 C 核对，不只让两套渲染互相证明。

## 2026-11-09 AOE 图表示与逐边时间更新

- **第 19–20 页**：AOE 是带权 DAG 数学模型；实际算法使用图的计算表示。当前 C 演示采用带权出邻接表，`head[u]` 和 `edge[e].next` 枚举事件 `u` 的出边；每条边提供终点 `v` 和时长 `w`。Python 动画生成器以 `outgoing[u]` 承担等价职责。用于时间计算的 `order` 是 **AOE 事件图本身**的拓扑序，不等于前面 AOV 活动图的拓扑序。
- **第 21 页**：从事件 2 的全部前驱约束导出最终时间，例如 `ve[2]=max(ve[0]+5,ve[1]+1)=5`；这是数学结果的定义，不是每一次动画点击执行的赋值。
- **第 22 页**：沿当前出边 `u→v` 得候选 `c=ve[u]+w`，有旧候选时使用 `ve[v]←max(ve[v],c)`；播放器中的“—”表示尚无候选，首次直接写入。所有前驱已传播后，才把该事件的值视为确定。C 演示在非负活动时长前提下以零初始化数值数组；不把这种实现初值等同于动画的未知状态。
- **第 26 页**：对称地按 **逆拓扑序**处理事件，但仍扫描原图从 `u` 出发的活动边，用已确定的 `vl[v]` 产生 `c=vl[v]-w` 并取 `min`；全部后继期限汇总后值才确定。
- **教学边界**：不在动画中堆叠完整 `Graph` 结构体；只要求能够追踪“原图输入与出边访问 → 当前弧与权 → 局部候选 → 更新后的事件状态 → 最终确定”的关系。数学对象、输入表示、算法状态和界面快照不能混同；工作流测试通过也不能代替课堂理解检验。

5. **计算机制**：正向依拓扑序处理 u，读取原图的出边 u→v 更新 `ve[v]`；反向依逆拓扑序处理 u，仍读取 u 的出边，以后继 `vl[v]` 更新 `vl[u]`。两种计算不修改原图，播放器“—”表示尚未汇总而不是零。
