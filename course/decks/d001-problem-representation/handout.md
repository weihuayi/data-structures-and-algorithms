## 迷宫：一个看似直观的选择

地图把通道、障碍、起点和出口表达出来。我们约定每次只能上下左右走一格。总选更接近出口的相邻格，在存在障碍时可能走入死路；为了继续探索，需要记住走过的地方、尚未尝试的方向以及返回路径。

当前阶段借此认识关系表达与操作顺序的作用。后续将讨论栈、队列与图怎样支持搜索。“找到一条路”和“找到最短路”是不同要求。步数与耗时也只有在每步耗时相同等条件下才能直接对应。

## 从空间位置到数学关系与数组

给迷宫每一行、每一列编号，本例均从0开始，行号向下增加、列号向右增加。格子用(r,c)表示。四个候选邻居为(r−1,c)、(r+1,c)、(r,c−1)、(r,c+1)。候选位置还必须在地图范围内，并且是通道，才能成为合法的下一步。

若两点均可通行，四邻域关系可以紧凑地写作|r−r′|+|c−c′|=1。这个等式描述“上下左右相邻”，不是完整的迷宫求解算法。一条路径是从起点到终点、相邻两项满足通行与邻接条件的位置序列。

在程序里，grid[r][c]访问该格子的编码值。此处约定0为障碍，1为通道：坐标回答“哪个位置”，数组值回答“该位置的通行属性”。起点和终点的坐标另外保存；只看0、1数组不能知道哪两个通道被指定为起终点。

合法下标范围为0 ≤ r < rows、0 ≤ c < cols。相应C表达为：

```
if (r >= 0 && r < rows &&
    c >= 0 && c < cols && grid[r][c] == 1) {
    /* 该候选格子可通行。 */
}
```

上式利用&&的短路求值，先确保范围合法，再访问数组。它只判断一个候选格子，尚未表达候选与当前位置是否相邻；邻接性由生成四个候选的步骤保证。矩阵形状提供熟悉的表格入口，本例主要使用元素访问和邻接关系，没有进行矩阵乘法。

地图数据也不等于完整求解状态。当前位置、已访问位置、待探索位置、返回路径等，需要在搜索过程中另外记录。地图发生变化时，这些记录是否仍然有效，也需要重新判断。

## 金额配对：先把任务说清楚

输入是一组商品及其价格和一个目标金额。找出不同的两件商品，价格之和等于目标；返回任意一组，没有解时明确说明。两件商品可以价格相同，但同一件不能使用两次。当前示例使用小范围整数，避免货币小数表示的额外问题。

例子：[18, 7, 25, 12, 33, 20]，目标32，有7+25和12+20。它们都是合法答案。程序返回哪一组由检查顺序决定。

### 枚举：不重不漏地检查

用i和j表示两件商品的位置，限定0 ≤ i < j < n。内层从i+1开始，因此不会把同一件商品与自己配对，也不会重复检查一对商品。任意两件不同商品都能按编号从小到大表示为唯一的(i,j)，所以不会漏掉。

检查一对时求和并与目标比较。找到任意一组即可返回；所有配对都检查完还没找到，就能报告无解。完整检查的配对数为(n−1)+(n−2)+…+1 = n(n−1)/2。提前找到时，实际次数可能更小。

## 从商品条件到候选配对

在初始记录顺序中，用i标记位置，pᵢ表示这个位置上的价格，C程序对应price[i]。目标金额T对应target。此教材小例子给每个商品赋予与原位置相同的编号，便于演示；在实际数据中，业务编号与存储位置通常需要分别保存。

不能使用同一件商品两次，产生条件i ≠ j。配对任务不关心两件商品的先后次序，因此(i,j)与(j,i)表达同一对。统一选择i < j，便可以对每个无序配对只保留一种表示。最终条件为0 ≤ i < j < n且pᵢ+pⱼ=T。

这个条件对应外层从i=0开始、内层从j=i+1开始，两个循环都限制下标小于n。若内层从0开始，且没有其他过滤，就会检查i=j，也会检查每对的两个顺序。例子{16}、目标32可暴露误用同一件的错误。

数学条件明确了哪些答案合法；遍历所有i < j是完成查找的一种算法。C中的==用于相等判断，=用于赋值，两者的用途要分清。

## 编译、运行和修改

本 Deck 的 [`code/pair_sum.c`](code/pair_sum.c) 是完整程序。Linux 演示可在 `code/` 目录中进行，命令如下；前提是已经安装gcc。

```
gcc -std=c11 -Wall -Wextra pair_sum.c -o pair_sum
./pair_sum
```

第一行将源码编译、链接成可执行文件；第二行运行当前目录的可执行文件。默认输出为：

```
indices: 1, 2
prices: 7 + 25 = 32
checks: 6
```

编号从0开始，因此1和2是第二、第三件商品。checks只统计配对检查次数，不是CPU指令总数。把target改为100并重新编译后，输出no pair和checks: 15。

修改源码之后必须重新编译。编译失败时，旧的可执行文件可能仍然存在；先修复报错并确认编译成功，再运行。练习阅读第一条报错中的文件名、行号和信息，检查该行及其附近代码。

在Windows等系统中，可以使用原C语言课程使用的开发环境。打开源码，执行对应的编译或构建操作，再运行新生成的程序。无需安装Linux或统一编辑器。可执行文件名称和运行入口可能不同，但“源码—编译—可执行程序—结果”的关系相同。

当前示例使用小范围整数价格，价格之和在int范围内。程序没有键盘输入解析；通过修改数组和target后重新编译来切换案例。
