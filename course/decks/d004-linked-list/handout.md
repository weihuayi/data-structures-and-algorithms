# D004 链表与表示的选择｜学生讲义

## 稀疏多项式的委屈，有解了

上次课留下的问题：$x^{10000} + 2x + 1$ 按"下标即次数"要开 10001 个位置的数组，其中 9999 个位置住着 0。本次课的答案：只给真正存在的项安排住处——这个多项式只需要三个住处。但"下标即次数"丢了，三个项散落各处，谁先谁后？次序不能靠"住在隔壁"表达了，还能靠什么？

## 结点设计：一个结点住什么

每一项自己报告三件事：

- **系数** coef；
- **次数** exp；
- **下一项住在哪** next。

前两个是**数据域**，最后一个是**链接域**。次序不再靠物理相邻，靠链接显式表达：每个结点指着下一个结点，一个接一个，次序就保住了。工程中的工序链是同一个思想：每道工序只登记下一道是什么。

## 寻宝游戏：为什么不能直奔第 5 个地点

回收 D003 的快递柜作对照：柜号直接算出格子位置，凭号码直接开柜；寻宝游戏里每条线索只写着下一个地点，想到第 5 个地点，必须从第 1 张纸条走起，沿着线索走 4 次。线索之于地点，正如 next 之于下一个结点。一个能直奔，一个只能沿着走——差别就在有没有"地址公式"。

## 内存中的结点与指针

回收 D002 的内存模型：内存是一个巨大的字节数组，指针 = 地址。结点在内存里散落各处，指针把它们串成链：

| 结点 | 住址（地址） | next（下一项住址） |
| --- | --- | --- |
| $3x^2$ | 100 | 316 |
| $2x$ | 316 | 208 |
| $1$ | 208 | 空（NULL） |

地址 100、316、208 互不相邻，链却串起了次序。head 只记录第一个结点的地址 100——这是整条链的全部家当。

## struct Node 与 malloc/free

结点在 C 里的样子：

```c
struct Node {
    int coef;           /* 系数           */
    int exp;            /* 次数           */
    struct Node *next;  /* 下一项住在哪   */
};
```

`malloc` 让结点出生：按需申请一个结点的住处，顺序表"住满要扩容"的问题消失了。`free` 让结点死亡：归还住处。自由是有代价的——内存管理的责任出现了：malloc 来的住处不归还，内存会一点点漏掉（内存泄漏）。

[`code/link_demo.c`](code/link_demo.c) 用三次 malloc 安排 $3x^2 + 2x + 1$ 的三项，打印每个结点的真实地址。先预测：连续三次 malloc，地址会相邻吗？运行检查：不会——结点由系统在空闲处安排，相邻结点之间隔着空隙，地址差不再是 `sizeof(Node)`。这与 D003 的 `addr_demo.c` 恰成对照实验：数组元素恒相邻，malloc 结点不相邻，但链得起来。同一个验证口径：先预测、再运行、再检查。

## 访问：O(n) 与新形态的不变量

地址公式失效了：结点不住在 $base + (i-1)\times L$，算不出，只能走。从 head 出发，沿 next 走 $i-1$ 步，到达第 $i$ 个元素。取第 1 项走 0 步，取第 $n$ 项走 $n-1$ 步，访问是 $O(n)$。

表示不变量换了形态：

- 顺序表：第 $i$ 个元素恒在 $base + (i-1)\times L$；
- 链表：从 head 出发沿 next 走 $i-1$ 步，恒到达第 $i$ 个元素。

数学接口：这正是递推——首项加递推关系，第 $i$ 项只能逐项推出；head 加 next，第 $i$ 个结点只能逐个走到。

## 插入：改两个链接，顺序重要

还是按学号插入新同学 104。链表里没有"腾出位置"这回事：插入只需改两个链接——新结点指向后继，前驱指向新结点。没有一个人搬家，到达插入位置之后，插入本身是 $O(1)$。火车挂摘一节车厢同理：只需解开两处挂钩，不必把后面的车厢全部移位。

先自己答：这两步先做哪一步？**先接后继，再改前驱。**若先把前驱指向新结点，链从中间断开，后继的地址被覆盖丢失，后半条链永远找不回来。断链是指针操作的经典陷阱：唯一的线索被覆盖，后面的世界就消失了。

## 删除：摘下结点不算完

删除分两步：第一步改链接，前驱跳过被删结点、指向它的后继；第二步 free，归还结点占用的内存。只改链接不 free，结点成了无家可归的孤儿——内存泄漏。改链接只是第一步，free 才是责任完成。

[`code/linklist.c`](code/linklist.c) 演示完整过程：尾插建立名单 $[101, 103, \dots, 115]$，按序插入 104（打印改链接的两个步骤），删除一个结点（打印 free 提示），可以逐条核对上面的分析。

## 顺序表 vs 链表：代价严格互换

| | 顺序表 | 链表 |
| --- | --- | --- |
| 按位置访问 | $O(1)$ | $O(n)$ |
| 插入 / 删除 | $O(n)$ | $O(1)$ |
| 空间开销 | 无额外 | 每结点多一个指针 |
| 容量 | 定长，需扩容 | 按需生长 |

强项与边界仍来自同一个原因：布局选择。换取一样东西的方式，就是放弃另一样东西。

## 什么时候用哪个

- **选顺序表**：访问为主、增删稀少；规模稳定、可以预估。
- **选链表**：增删频繁、位置多变；规模不定、难以预估。

呼应 D003：没有最好的表示，只有适合任务的表示。操作模式，决定表示选择。

## 变体：循环链表与双向链表

- **循环链表**：尾结点的 next 回头指向 head，从任何一处出发都能走完全程。约瑟夫问题——围成一圈报数出局——是天然的循环。
- **双向链表**：每个结点多付一个 prev 指针，换反向行走的自由。

本课只讲动机，不展开实现。可以想一想：循环链表遍历的终止条件怎么写？双向链表插入要改几个链接？

## 应用回收：两个有序链表合并

回收 D002 的双指针扫描：两个指针各盯一条链的当前结点；比较所指结点，把较小的接到结果链尾部，对应指针前进一步，直到一条链走完。数组版合并要逐个元素拷贝；链表版只改链接、不搬数据——现成的结点只是被重新串联。

## 回到教材：链式存储结构与 ADT 的第二种实现

教材 2.5 节的定义：

> 链式存储结构用一组任意的存储单元存储线性表的数据元素；每个结点除存储数据元素本身的信息外，还要存储指示其直接后继的信息。

数据域 + 指针域 = 结点；$n$ 个结点链接成一个链表。每个结点只含一个指针域的，称为单链表（线性链表）。这是线性表 ADT 的**第二种实现**：操作集合没变，存储方式换了——教材 2.2 节"ADT 不规定怎样存"，在此兑现。一元多项式相加的完整实现见教材 2.8 节，作为习题路径。

## 本质收口：抽象与表示分离

InitList、GetElem、ListInsert、ListDelete……操作集合一个没变，变的只是元素"住"的方式。线性表这个抽象对象，与它的物理表示是分离的：**表示是服务抽象对象的方式，不是对象本身。**这条元认识将反复回收——栈、队列、树、图，都会面对"同一抽象、多种表示"。
