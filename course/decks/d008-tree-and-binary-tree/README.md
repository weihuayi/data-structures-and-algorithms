# D008｜树与二叉树：层次组织

## 设计卡：本质关系

层次关系本身是计算对象的一部分。名字的集合不足以回答归属问题，表示必须保存父子关系及相应约束。双亲数组与孩子表可以保存同一棵树，却对上行、下行操作提供不同能力。二叉树进一步要求左、右位置明确，缺失的位置也携带信息；数组和二叉链表又是这一对象的不同表示。

认知焦点为 PO（问题到对象）与 REP（计算表示）。回收 D003/D004 的抽象对象与物理表示分离、D006 的递归定义与 D007 的信息保留。性质推导服务于理解表示条件，不把本讲扩成遍历算法课或查找树课。

设计依据：`course/data_structures_algorithms_learning_progression.md`（v0.2 候选）与 `course/data_structures_algorithms_D001_D020_learning_progression_matrix.md`（v0.1 候选）的 D008 条目，以及 WhyOS《数据结构与算法课程》结构化理解 Memo v0.3 的“树：关系结构”定位。这些设计依据不构成课堂运行或学习达成证据。

- **数学**：算式的结合结构与左右操作数；递归定义；按结点与边两种方式计数。高度按层数计，根为第 1 层，空树为 0。

## 主要问题与案例

问题链：只存名字丢掉什么 → 什么条件组成树 → 怎样把关系存入程序 → 操作代价如何变化 → 修改必须保持什么 → 左右位置为何重要 → 什么形态适合位置数组 → 换一个对象能否独立选择。

- 主案例 A：A 实验资料，B 模型，C 结果，D 网格，E 参数，F 图像，G 报告。双亲依次为 −1、A、A、B、B、C、C。
- 主案例 B：`(a-b)*(c+d)`，7 个结点，4 个叶子，高度 3，满树最大位置为 7。
- 反例：B 移到 D 下形成环；只有右孩子与只有左孩子；4 结点右单链位置 1、3、7、15。
- 独立迁移：先由查询需求识别实体或展出记录，再展开四层、单归属约定；多归属变体要求重新判断对象或关系模型。

## 维护与验证

- `slides.py`：主源，25 页，使用共享语义样式和原生折叠注记。
- `index.html`：运行 `python3 tools/deck/build.py D008` 生成。
- `code/tree_demo.c`：C11 单文件演示，自带边界断言。递归统计仅用于运行核对，D009 再展开算法。

从本目录运行：

```bash
gcc -std=c11 -Wall -Wextra code/tree_demo.c -o /tmp/d008-tree
/tmp/d008-tree
```

先预测，再运行，再核对：

```text
experiment: n=7 leaves=4 height=3 max_position=7
expression: n=7 leaves=4 height=3 max_position=7
right-chain: n=4 leaves=1 height=4 max_position=15
empty: n=0 leaves=0 height=0 max_position=0
parent-cycle: rejected
All classroom checks passed.
```

断言覆盖空树、单结点、仅左/右孩子、删去右子树、无根、多根、自环、两结点环、越界和非法负编号。指针统计只接受合法树，位置编号须能用 `size_t` 表达；不是任意深度、不可信指针图的校验器。双亲校验器最坏 O(n²)，仅用于小规模课堂输入。
