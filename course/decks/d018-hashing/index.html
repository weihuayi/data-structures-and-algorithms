为什么不能直接以学号作为数组下标？

学号可能很大且稀疏，实际存储的记录却很少。

直接寻址：若把关键字直接作为下标，需要覆盖巨大的地址范围；大量单元可能未使用。
问题条件计算与空间判断

这里讨论空间利用；不预设具体机器内存规模。

第二部分 · 从直接寻址到散列映射

散列函数计算的是哪一个位置？

散列（Hashing）：把关键字映射到有限的初始地址空间。

\(h(k)=k\bmod m\)，本例 \(m=7\)，地址为 0–6。

示范计算：\(h(10)=3\)。其余关键字的地址留到下一页独立计算。

对象意义
k关键字（Key）
m桶数组或槽位数组长度（容量）
h(k)由关键字计算的初始候选地址

不同关键字可以有相同散列值；函数不必取遍全部地址。

第二部分 · 从直接寻址到散列映射

四条记录都能直接放到算出的地址吗？

共同输入：非负整数键，按顺序插入 \(10,17,24,13\)；\(m=7\)，\(h(k)=k\bmod7\)。
如果每个数组位置只能保存一条记录，直接按照 h(k) 存入，会遇到什么问题？
核对答案与理由

10、17、24 的散列地址都是 3，三个不同关键字竞争同一个槽位。这叫散列冲突（Collision）。初始地址是候选位置，并非完整查找结果；必须设计冲突处理规则。

只查一个桶，就能断定不存在吗？

核对答案与理由

\(h(24)=h(31)=3\)，都只需检查桶 3。查找 24 比较 10→17→24，成功；查找 31 比较全部三个记录，没有相等关键字，失败。因为所有已有记录始终按其 h(k) 归入对应桶，其它桶不可能含该键。

第三部分 · 怎样处理映射冲突

链地址法与线性探查的结构性质相同吗？

比较对象链地址法线性探查
数组位置代表什么桶（链表入口）能保存一条记录的槽位
冲突后的记录在哪里同一桶的链表中顺着探查序列的其它槽位中
关键正确性要求记录属于 h(k) 所在桶查找与插入使用同一探查路径
装载因子 n/m每桶平均记录数有效槽位占比，不能超过 1

相同符号 m 表示数组容量，但数组单元承载的含义不同。

第四部分 · 操作怎样保持正确

查找 24，需要经过哪些位置？

共同输入：非负整数键，按顺序插入 \(10,17,24,13\)；\(m=7\)，\(h(k)=k\bmod7\)。
沿线性探查规则查找 24。写出每一步位置及是否继续或终止。
核对答案与理由

\(h(24)=3\)。在 3 比较 10，在 4 比较 17，在 5 找到 24。因此访问路径为 3 → 4 → 5，共检查 3 个槽位。

第四部分 · 操作怎样保持正确

删除 17，为什么不能简单改成 EMPTY？

共同输入：非负整数键，按顺序插入 \(10,17,24,13\)；\(m=7\)，\(h(k)=k\bmod7\)。
删去 17 后，如果把位置 4 改为 EMPTY，再查找 24，会发生什么错误？
核对答案与理由

查找 24 从位置 3 出发，在位置 4 遇到 EMPTY 就会被错误地判为不存在，尽管位置 5 仍存有 24。采用墓碑策略应将位置 4 标为 DELETED。

第四部分 · 操作怎样保持正确

查找 31，应当在哪里停止？

当前状态：已删除 17，位置 4 是 DELETED。

给定 \(h(31)=3\)，写出查找 31 的完整探查路径，并说明失败依据。
核对答案与理由

3 → 4 → 5 → 6 → 0，位置 0 为 EMPTY，才可判定不存在。不能在位置 4 的 DELETED 停止。共检查 5 个槽位，其中仅与 3 个有效关键字比较。

第四部分 · 操作怎样保持正确

三种状态怎样共同保证操作正确？

已存关键字在其探查路径上，不得被提前遇到的 EMPTY 隔断。

三种状态与查找规则
状态操作
OCCUPIED比较键；不相等继续
DELETED继续，不能判定失败
EMPTY正确判定不存在
C11 查找分支节选 
/* p 已由 position(key,i) 得到 */
if (t->slot[p].state == EMPTY)
    return -1;
if (t->slot[p].state == OCCUPIED
    && t->slot[p].key == key)
    return (int)p;
/* 其余情况继续探查 */

循环最多执行 m 次；插入遇到 DELETED 要记住可复用位置，但仍须继续检查是否存在重复键（见下一页）。节选省略轨迹输出与计数。

第四部分 · 操作怎样保持正确

墓碑出现后，插入时能立刻占用吗？

现在依次考虑插入已有键 24，以及新键 31。

遇到位置 4 的 DELETED 时，能否立即插入 24？插入新键 31 后最终表怎样变化？
核对答案与理由

不能立即写入 24，因为位置 5 已有该键，字典要求键唯一。继续检查直到命中 24，判定重复。对于 31，确认沿路径 3→4→5→6→0 不存在后，复用已记住的位置 4。

第五部分 · 查找代价为什么不同

成功查找的平均长度如何算？

共同输入：非负整数键，按顺序插入 \(10,17,24,13\)；\(m=7\)，\(h(k)=k\bmod7\)。
如果四个已有键被等概率查询，请分别写出各键成功探查次数并计算 ASL。
核对答案与理由

10、17、24、13 的探查次数分别为 1、2、3、1。

\(ASL_{succ}=(1+2+3+1)/4=7/4=1.75\)。这是对给定四个键的等概率成功查询的条件平均，不是任意失败查询的平均。

第五部分 · 查找代价为什么不同

失败查找的平均长度如何计算？

给定输入：容量 \(m=7\)，\(h(k)=k\bmod7\)；依次插入 \(10,17,24,13\)（互异的非负整数键）。

表为插入四个键后的初始状态（尚未删除）。设失败查询的初始散列地址 \(r=0,1,\ldots,6\) 各以 \(1/7\) 的概率出现；按检查槽位次数计费。

对于七种初始地址，分别写出查找不存在关键字时的探查次数，再计算失败 ASL。为什么不能把它与上一页的成功 ASL 混为一谈？
核对答案与理由
失败查询的初始地址 r0123456
槽位探查次数1115432

\(\displaystyle ASL_{\mathrm{unsucc}}=\frac{1+1+1+5+4+3+2}{7}=\frac{17}{7}\)。该平均值以失败查询的初始地址均匀分布为前提；上一页 \(7/4\) 是对四个已存关键字等概率查询的成功 ASL，两者的概率空间不同。

第五部分 · 查找代价为什么不同

同样装载因子，查找代价也相同吗？

两组不同关键字按序插入，均用 \(m=7\)、\(h(k)=k\bmod7\)、线性探查。

\(S_1=(3,4,5,6)\)，\(S_2=(3,10,17,24)\)。

两组都是 \(\alpha=4/7\)。计算两种情况下等概率成功 ASL，并说明不同原因。
核对答案与理由

\(S_1\)：所有记录初始地址就是实际位置，ASL=1。\(S_2\)：四个键初始地址均为 3，探查次数 1、2、3、4，ASL=2.5。

装载因子相同不足以确定查找成本；分布、散列函数和探查路径仍起作用。这里两表的失败查找长度不会仅因为成功 ASL 不同而自动不同。

第五部分 · 查找代价为什么不同

跳过相邻槽位，就一定能找到空位吗？

二次探查改变访问次序，必须声明具体的增量规则与表长。

教材 7.4.3 的双向平方探查：以初始地址 \(h(k)\) 为基点，按 \(d_i=0,+1^2,-1^2,+2^2,-2^2,\ldots\) 尝试，并对槽位容量 \(m\) 取模。

例如 \(m=8,\ h(k)=4\)：前几次访问 4 → 5 → 3 → 0 → 0 → 5 → 3……，并未覆盖全部槽位。

教材选择题 (14) 用表长 14、\(H(key)=key\bmod11\)；应用题 (6) 另外限定只取正平方增量。按各题明示的规则演算，初始散列取模常数不必等于数组容量。

第五部分 · 查找代价为什么不同

为什么不能无条件说“散列查找 O(1)”？

分析对象结论成立的条件
单次最坏查找开放定址 O(m)；若 m=Θ(n) 则 O(n)。链地址法最坏 O(n)
期望 O(1) 查找需要适当的散列分布假设、受控装载因子和单位成本模型
动态维护墓碑、扩容会改变实际成本；一次重建可能为 O(n)
与 AVL 比较AVL 最坏 O(log n)，并支持有序区间查询

m 是槽位容量，n 是有效记录数；单次最坏界、概率期望和摊还成本不能互相替代。

设备编号查询与区间查询，应如何组织？

某系统维护设备编号及状态：多数请求按编号精确查找，同时还需要按编号区间查询。允许根据需求组合索引，但每次更新必须保持索引一致。

比较单独使用散列表、AVL 或双索引方案：各自的优势、代价和可能改选条件是什么？
核对答案与理由

精确查找占主导且接受期望保证：散列表是候选；频繁区间查询且要求有序输出：AVL 等有序结构具有直接优势；两种操作都很关键时可组合索引，但增加存储、更新与一致性维护成本。不能脱离频率、规模及最坏延迟要求给出唯一最优方案。
