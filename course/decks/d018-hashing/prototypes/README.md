# D018 R5｜真实视觉原型 P2 / P4

> **状态**：R5 首批原型；仅供教师审阅与设计验证。**不是正式课件**，不修改 `slides.py`、`index.html`、课程课后 A/B 作业或真实授课记录。

## 设计目的

依据 D018 R4-C7 至 C11 及 R5-C1 至 C3，优先验证两个承重认知机制：

- **P2 首次线性探查**：初始地址 `h(17)=3`，位置 3 存在 `10`；通过“先检查再写入”的连续状态，区分计算地址、检查位置、实际落位。一步示范后，后续页面需要对 `24,13` 进行独立构造，不能在本原型提前展示全部表。
- **P4 删除正确性**：初始状态 A、错误分支 W、恢复合法状态 A、正确墓碑状态 B、归纳探查路径不变量。**W 是反事实分支，不允许从 W 继续执行正确操作**。本原型只验证 `find(24)` 的漏查反例和修复依据，`find(31)`、重复键检查及墓碑复用留待独立页面 / 后续 P3。

本原型的全部内容以静态 HTML + CSS + 确定性 JS 状态驱动，在没有 AI 的情况下可通过本地浏览器运行。没有网络依赖、自动轮播、复杂物理动画，也不引入新的全课程组件。

## 浏览与操作

直接打开 `r5-two-core-prototypes.html`，顶部在 P2 / P4 间切换；底部的“下一步 · 揭示”“上一步”“重置场景”由教师手动控制。键盘左、右方向键亦可控制当前原型的步骤；初始展示状态不泄漏完成结果。`P4` 各步骤具有状态身份 A/W/A/B/B，且保留原问题和容量、散列函数约定。

## 原型设计与专业边界

- 两个原型的槽位 0–6 始终占据固定位置；**槽位状态**、**当前检查动作**、**访问路径**分别表示；颜色只作强调，关键状态同时使用文字。
- P2 的记录 17 在检查位置 3/4 时仍处于表外；直到确认 EMPTY 后才写入。
- P4 的 W 分支明确标注“假设错误删除”；下一步回到 A，而不是将错误状态当作合法演化。
- 原型使用非负整数键、容量 7、线性探查，展示墓碑删除策略。其它开放定址删除策略可能采用搬移重组，本原型不作普遍化。
- 完整动态正确性还需要 `find(31)` 的失败停止、重复插入 `24` 与新键 `31` 的墓碑复用；本批原型没有展示，也不能据此宣称已验证完整字典契约。
