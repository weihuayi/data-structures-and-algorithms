# D018｜Storyboard：从候选地址到可靠的散列查找

> **状态**：基于 D018 R1–R3 已接受的专业与教学候选认识，对已实现的 31 页课件开展认知路径对照与修订设计；**不是**已经完成的教师审阅或课堂效果证据。  
> **核对对象**：`feat/d018-hash-table-lesson` 分支的 [设计卡](README.md)、[页面主源](slides.py)、[生成课件](index.html) 及 [C11 示例](code/hash_demo.c)。当前页面 ID、顺序、标题与元数据以 `slides.py` 为唯一事实主源，本文件只维护跨页认知关系与候选修订理由。  
> **主要用途**：回答每个关键页面“学生此前凭什么理解？本页要形成什么新认识？下一页为何能够依赖它？”；对现有页面进行压力测试，而不是复制 README 的教学目标或重新定义课件页面。  
> **时间**：沿用 README 的 90 分钟候选预算，非真实授课计时。页面增删、合并或调序必须以学习活动为依据，并同步校正本文件的稳定 ID 对照。

## 一、教学中心和专业—教学边界

**主问题**：不依赖关键字大小顺序，怎样通过计算映射快速定位记录，并在冲突和动态更新中保证查找正确？

四项目标：G1 **映射定位**、G2 **冲突与正确性**（主重心）、G3 **有条件的代价评价**、G4 **结构选择**。本 Storyboard 将它们组织为三次真正的认知跨越，而非把教材小节直接转成页面：

1. **从比较到地址计算**：由 D016/D017 的比较和顺序关系，转向由键计算初始地址；但 **h(k) 不是查找结果**，这由冲突反例建立。
2. **从可放入记录到正确维护字典**：链地址与开放定址的结构规则不同；正确的插入、查找、删除及去重必须共同保持对应不变量。尤其不能将 DELETED 当作 EMPTY。
3. **从“做对一次”到条件化选择**：ASL 依赖探查/比较口径与查询分布；相同装载因子不确定唯一代价；散列表的期望优势不取代 AVL 的最坏界与有序能力。

**教学上不可省略**的是学生独立完成关键操作并解释原因；教师完整掌握通用散列证明、扩容摊还与其它探查策略，不意味着一讲里都要展开。已讲过 D016/D017 不等于相关先修能力已经形成，应通过短诊断确定实际起点。

### 需要独立验证的数学口径

- **成功 ASL**：初始键按顺序 10、17、24、13 插入 `m=7` 的线性探查表，各自成功探查数 1、2、3、1，等概率平均 `7/4`。
- **删除状态**：删除 17 后位置 4 为 DELETED；查询 24 走 3→4→5 成功；查询 31 走 3→4→5→6→0，遇真 EMPTY 后失败，按检查槽位计 5 次。
- **失败 ASL 候选题（尚未进入课件）**：保持删除前初始表，假设不存在的待查键按初始地址 \(r=0,1,\ldots,6\) 等概率分布。各自失败探查次数为 \((1,1,1,5,4,3,2)\)，所以 \(ASL_{unsucc}=17/7\)。这不是无条件期望公式；必须声明查询模型、状态与代价单位。删除 17 改作墓碑后，这一组按地址计的失败探查长度仍不变。
- **表容量与取模常数**：教材习题候选中存在数组长度 18、初址 `key%16` 的配置；初始地址计算与后续探查环绕必须分别使用题设定义与数组容量，不可混淆。
