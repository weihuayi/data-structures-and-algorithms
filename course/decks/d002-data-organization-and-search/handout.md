# D002 数据组织如何改变搜索｜学生讲义

## 为什么想到先排序

原价格为[18,7,25,12,33,20]，目标32。枚举能找到答案，但一次失败通常只排除一对。例如18+7=25不够，并不能由此推出18与其他商品也不够。

如果选择最便宜的7和最贵的33，7+33=40已经超出目标。其余价格p都不小于7，所以33+p≥40>32。由最小值提供的界限，可以排除与33有关的全部五对。

排除33后，若想重复这种判断，需要继续取得剩余价格的最小值和最大值。可以反复遍历寻找；这里尝试预先排序，让剩余范围两端直接给出极值。排序因此回应了算法的操作需要，它并非唯一选择，且预处理成本必须计入总成本。


### 排序之后重新检查对应

排序后的价格记为a[k]，k是新位置，不继续把它默认为原商品编号。

|  |  |  |  |  |  |  |
| --- | --- | --- | --- | --- | --- | --- |
| 新位置k | 0 | 1 | 2 | 3 | 4 | 5 |
| 有序价格a[k] | 7 | 12 | 18 | 20 | 25 | 33 |
| 原编号 | 1 | 3 | 0 | 5 | 2 | 4 |

例如新位置0对应原编号1，价格为7。价格与原编号必须一起移动，或通过索引保持对应。若原登记顺序也需要保留，可以保留原记录并建立另一份按价格排序的索引。当前阶段理解这层关系，不要求独立实现记录排序。

## 有序性怎样减少检查

把价格非降序排列为[7, 12, 18, 20, 25, 33]。用两个整数索引L、R标记左右位置，初始L=0、R=n−1，只在L < R时检查。本讲义把这种实现称为**双索引扫描**；算法资料中也常称为双指针（two-pointer）方法。这里的L、R在C程序中是整数数组索引，不是指针类型。若和恰好为目标，返回；和太小，L向右移；和太大，R向左移。

### 为什么移动左端不会漏解

若a[L]+a[R] < T，由有序性，对L < k ≤ R都有a[L]+a[k] ≤ a[L]+a[R] < T。因此当前左端与剩余任何其他元素都不能构成解，可以排除左端。

### 为什么移动右端不会漏解

若a[L]+a[R] > T，对L ≤ k < R都有a[k]+a[R] ≥ a[L]+a[R] > T。因此当前右端与剩余任何其他元素都不能构成解，可以排除右端。

每次只排除已证明无法参与解的端点，因而尚可能存在的解仍在剩余范围内。每次未成功的迭代缩小范围，最终找到解或剩余不足两件，所以算法会终止。

### 前提不能省略

两件价格相同的商品仍占据不同位置。[16,16]可以凑32，[16]不可以；L < R保证了这一点。若直接对未排序数组[18,7,25,12,33,20]使用同样规则，依次比较18+20、18+33、18+12、7+12、25+12，最后会错误报告无解。这个反例说明有序性是理由的一部分。

[`code/pair_sum_sorted.c`](code/pair_sum_sorted.c) 只实现已经排序的数据上的扫描，输入数组预先写成有序形式。它不包含排序步骤，输出的位置属于排序后的数组。需要返回原商品编号时，应把价格与原编号一起保存和排序，或维护相应索引关系。课堂网页显示了这种对应。

## 正确地比较时间与空间

对n ≥ 2的有序数组，双索引扫描最多检查n−1对，因为每次未成功的检查使R−L减一。从无序数据开始，总成本还包含排序。若使用最坏O(n log n)的排序算法，整体时间为O(n log n)，有序数组上的扫描为O(n)。不同排序实现的保证应单独核对。

时间复杂度关注执行时间随问题规模的增长，当前按基本操作次数分析。大 O 记号表示渐近增长上界；不将其解释为精确相同的增长率。这里先关注主要量级，正式定义在后续学习。枚举最坏时间为O(n²)。这里按小整数算术和数组元素访问为常数代价计数。

枚举和有序扫描本身都只需常数个辅助变量；排序所需空间由排序实现决定。若为了保留原顺序而复制数据，副本占O(n)空间；保存原编号也增加存储。空间复杂度描述空间需求随问题规模的增长。当前比较额外辅助空间；原始输入数组的空间与额外辅助空间需要分清。另建包含 n 个位置的排序索引，占 O(n) 的额外空间。

比较必须统一输入、目标和停止规则。只统计配对检查时，要说明没有统计排序；比较端到端运行时间时，则应纳入排序等必要工作。几组测试通过可以增加信心、发现错误，但不能代替算法的一般正确性理由。

## 从商品记录进入数据结构专业术语

现实中的一件商品包含名称、编号、价格、类别等信息。配对任务需要判断价格之和，并能指出是哪两件商品，因此至少需要保留编号与价格。在这个案例中，编号、价格等可供计算机处理的信息是数据。计算时需要根据任务选择信息，现实对象与它的数据表达应当区分。

### 数据对象、数据元素与数据项

用 $e_i=(id_i,p_i)$ 表示一条商品记录。记录作为一个整体被组织和处理，对应一个数据元素；编号、价格是组成记录的数据项。具有共同属性的商品记录所构成的集合，可用于理解数据对象的集合含义。

这些是结合当前案例的解释。在本例中，记录与数据元素、字段与数据项建立对应；这种对应依赖当前建模，不能把字段或记录的形式当作所有数据对象的固定形式。

### 逻辑结构

教材第一章小结指出，逻辑结构是从具体问题中抽象出来的数学模型，从逻辑关系上描述数据，与数据的存储无关。

本例中，商品记录按先后次序组成线性序列。按登记次序排列和按价格排列都可以是线性结构。排序改变了记录间的先后关系，并使价格满足非降序。线性结构与价格有序是不同层次的描述；双索引扫描依赖后者给出的大小界限。

教材列出四类基本逻辑结构：集合结构、线性结构、树形结构和图状结构。它们分别强调同属一个集合、先后、分支层次和一般连接等关系。后续课程结合线性表、栈、队列、树和图继续学习。

### 抽象数据类型

教材第一章小结中的定义：

> 抽象数据类型是指由用户定义的、表示应用问题的数学模型，以及定义在这个模型上的一组操作的总称。

抽象数据类型（Abstract Data Type，ADT）包括数据对象、数据对象上关系的集合，以及对数据对象的基本操作的集合。

| 组成部分 | 商品记录序列中的案例对应 |
| --- | --- |
| 数据对象 | 具有本任务所需共同属性的商品记录的集合 |
| 数据对象上关系的集合 | 记录之间的先后关系 |
| 基本操作的集合 | 求长度、按位置取得记录等操作 |

屏幕上的六条记录是一个具体例子。同样的模型与操作要求还应适用于其他数量、其他内容的商品记录。本讲选取相关操作举例，完整操作集合在后续学习线性表时展开。

以“按位置取得记录”为例：给定记录序列及位置 $k$，序列长度为 $n$；条件为 $0\leq k<n$；结果是返回该位置的商品记录，原序列保持不变。

对排序后的记录序列，$k=2$ 对应 $(0,18)$，即原编号为 0、价格为 18。操作说明规定了条件和结果，尚未规定必须采用哪一种存储方式。空序列没有合法的取记录位置，但仍可以求长度。

### 存储结构与操作实现

教材第一章小结中的表述：

> 存储结构是逻辑结构在计算机中的存储表示，有两类存储结构：顺序存储结构和链式存储结构。

本例可以用两个对应数组 `price[k]` 和 `id[k]` 保存价格与原商品编号。同一位置上的两个值共同表示一条记录，数组位置承载当前先后次序。取得位置 $k$ 上的完整记录，需要读取相应的编号与价格。

逻辑上的线性关系与数组这种具体表示需要区分。同一种逻辑结构可以采用不同存储方式，操作要求可以保持一致，而实现方法和代价可能不同。

### 数据结构与算法

教材第一章小结对这门学科的描述是：

> 数据结构是一门研究非数值计算程序设计中的操作对象，以及这些对象之间的关系和操作的学科。

教材从逻辑结构和存储结构两个方面讨论数据结构。商品案例同时涉及记录、先后关系、具体数组表示及所需操作。

教材中的算法定义：

> 算法是为了解决某类问题而规定的一个有限长的操作序列。

对已经按价格非降序排列的数据，扫描算法初始化左右索引，在 $L<R$ 时取得两端价格、求和、比较，按条件返回或移动索引，最后给出配对或无解结果。它通过顺序、分支和循环组织操作。“操作序列”不意味着只能顺序执行。

算法可以使用 ADT 提供的操作；ADT 的一项操作也可以由算法实现。求长度、取记录等操作的要求，与某个具体算法的执行流程应当区分。

课堂网页保存价格与原编号的对应关系；`code/pair_sum_sorted.c` 只保存有序价格，返回排序后的位置。若要求原商品编号，还需要保存并使用相应映射。

### 算法的五个特性

| 特性 | 含义与本例中的体现 |
| --- | --- |
| 有穷性 | 对每个合法输入，在有限步内结束；扫描每次未成功时缩小范围 |
| 确定性 | 每一步含义明确；和值比较结果明确决定下一步动作 |
| 可行性 | 操作能够通过有限次基本操作实现；本例采用小整数取值、求和、比较及索引更新 |
| 输入 | 一般可以有零个或多个输入；本例输入为已排序记录序列与目标金额 |
| 输出 | 一般有一个或多个输出；本例给出一组配对或无解结果 |

输入不限定为键盘输入，预先给定的数组同样可以是输入。无解可以是合法输出。如果删去索引移动，有限行代码可能反复检查同一对，因而描述有限不能代替执行终止的理由。

### 算法评价

教材列出正确性、可读性、健壮性和高效性四个评价方面。

| 评价方面 | 检查问题 |
| --- | --- |
| 正确性 | 在规定输入条件下，结果是否满足任务要求？ |
| 可读性 | 算法描述和程序是否便于理解、检查与维护？ |
| 健壮性 | 对异常输入或不适当使用，是否有合理处理？ |
| 高效性 | 时间与空间代价是否适合任务规模和使用条件？ |

确定性不能代替正确性。若宣称算法适用于无序价格，却直接使用双索引扫描，步骤即使明确并能结束，结果也可能错误。若明确要求输入有序，则该要求属于算法前提。处理违反前提的输入，需另行约定检查和响应方式。

## 把任务看作一次数据查询

金额配对可以看作从商品记录中找出满足条件的两条不同记录。除了公式，还需要关心记录身份、字段含义、结果如何对应原商品，以及数据如何访问。

只有几件商品时，简单枚举就可能足够。数据规模增加时，配对数量、访问方式和额外存储开始影响计算是否可承受。只查一次与反复查询，也会改变预处理是否值得的判断：多个目标查询可复用同一份排序结果，但每次仍有扫描成本；价格更新后，有序性或已有结果可能失效，需要维护或重建。

这是与数据处理视角建立初步联系。大数据技术还涉及更多问题，不能只用数量大小定义；当前阶段也不要求使用分布式平台。
