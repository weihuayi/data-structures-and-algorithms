## 一、课堂主问题与专业范围

本讲主问题：**面对无序的记录，怎样通过可解释的中间性质逐步建立正确的有序排列，计算代价为什么随机制和输入而变化？**

排序对象是由可比较关键字及记录身份组成的有限序列；合法排序输出应满足关键字非递减、有序性、排列保持和终止性。**稳定性**表示等关键字记录的原相对顺序不变，属于附加性质，不是对“正确排序”的替代定义。课堂算法采用从 0 开始的数组下标和 C11 语言；相等关键字必须通过不同记录身份辨认。

本讲深入学习直接插入排序（有序前缀）与快速排序（枢轴划分、左右递归）。折半插入、希尔排序提供机制改进对照；冒泡排序必须让学生独立理解一轮相邻交换和已确定后缀。希尔复杂度依赖增量序列，不作固定的 \(O(n\log n)\) 断言；快速排序区分均衡划分、最坏及随机枢轴的期望条件。

D020 继续选择排序、堆、归并和分配排序，以及面向真实需求的统一方法比较。本讲不提前取代 D020 的教学目标。

## 四、算法与表示的具体约定

- **直接插入**：将新记录暂存；从前缀尾部严格比较 `a[j-1].key > x.key` 才右移。记录身份多重集合保留；相等关键字不发生越过，因此稳定。过程图中的 `□` 是逻辑空位，不是 C 中真实“空值”。
- **折半插入**：使用上界位置，将新记录插入在已有相等关键字之后以保持稳定；虽然定位比较减少，记录后移在最坏情形下仍为平方量级。
- **希尔排序**：明确课堂示例的具体增量 `2→1`；反例 `2_a,2_b,1_c → 1_c,2_b,2_a` 显示可能不稳定。C11 教学程序另使用已声明的 `5,3,1` 增量，不把二者误称同一段执行轨迹。
- **冒泡**：从左向右严格逆序才交换；每轮未确定区域最大元素进入已确定后缀；一趟无交换即可停止。
- **快速排序**：首元素暂存为 pivot，右端先搜索 `<pivot`，左端后搜索 `>pivot`，交替搬移填补逻辑空位；停下写回 pivot。允许左 `≤pivot`、右 `≥pivot`，内部无序。该双路规则在全部相等等输入下可能极度不均衡，常规实现不稳定。
- **成本**：明确“关键字比较”“记录赋值”“交换”和递归工作量的计数口径；不将期望性能推广为最坏保证。

关键例子：直接插入 `[2,4,7,3,6]`；稳定性 `[5_a,2_b,4_c,2_d,3_e]`；Partition `[4,7,2,8,3,6,1] → [1,3,2,4,8,6,7]`；独立划分 `[5,9,3,8,2,7,4,6,1] → [1,4,3,2,5,7,8,6,9]`，枢轴最终下标 4。所有状态应由独立 C11 与 JS 测试交叉核验。

## 五、C11 教学程序与正式作业

正式 C11 入口：[`code/sorting_demo.c`](code/sorting_demo.c)。支持 `insert`、`binary`、`shell`、`bubble`、`partition`、`quick`、`--self-test`；可额外传入整数关键字列表。记录以 `(key,id)` 表示，`id` 自动按输入下标赋值，便于检查身份和稳定性。

本地编译与核对（在本讲目录执行仅为展示相对路径；学生可以把源码放在自己的电脑的任何本地目录）：

```bash
gcc -std=c11 -Wall -Wextra -Werror -pedantic code/sorting_demo.c -o sorting_demo
./sorting_demo insert 5 2 4 2 3
./sorting_demo partition 5 9 3 8 2 7 4 6 1
./sorting_demo --self-test
```

**本讲最后一页是唯一正式 A/B 作业任务主源。** A：教材第 8 章选择题 (1)(3)(6)(7)，应用题 (1) 中的 ①直接插入、⑤快速排序；B：预测指定输入，再独立运行 C11 核验、解释一次正确性保持和输入相关成本。选做应用题 (1) 的 ③希尔以及算法设计题 (4)。教材习题候选来自 [第八章习题核对草案](../../../docs/design/exercise-candidates/ch8.md)，正式编号以最后一页为准。

共同要求以 [`course/assignments/homework-guide.md`](../../assignments/homework-guide.md) 为准：3–5 行过程记录；必要时附修改的代码；学生本地运行，非强制 Git 仓库、GitHub Push 或运行截图；按助教通知的飞书渠道提交。若 D019/D020 同周收取，需检查累计任务负担。
