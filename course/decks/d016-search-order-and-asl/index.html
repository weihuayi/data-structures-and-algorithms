第二部分 · 利用有序信息

为什么不会漏查，也不会停住？

保留可能命中的记录

若目标存在，仍在当前候选区间。

每次根据有序性，只排除已经确定不可能命中的位置。

未命中时继续推进

已经比较且不相等的中点也要排除。

区间长度严格减小；命中或区间为空时结束。

初始覆盖全表；更新保持候选不漏；终止时由相等或空区间给出结果。两项理由分别承担结果正确与能够结束。

第二部分 · 利用有序信息

区间规则怎样进入 C 程序？

int binary_find(const int a[], int n, int key) {
    int low=0, high=n-1;
    while (low<=high) {
        int mid=low+(high-low)/2;
        if (a[mid]==key) return mid;
        if (a[mid]<key) low=mid+1;
        else high=mid-1;
    }
    return -1;
}

核心代码省略轨迹记录。演示仅存关键字，一般记录还需保持其他字段对应。前提：n≥0、存储有效且按同一关键字非递减；查询不现场排序。

第三部分 · 计算查找代价

怎样从不同查询得到平均代价？

教材定义（概述）：平均查找长度（Average Search Length，ASL）是比较关键字个数的期望。教材首先定义成功时的 ASL；此时概率在成功记录之间归一。

\(ASL_{\mathrm{succ}}=\sum_{i=0}^{n-1}p_i c_i,\qquad \sum_i p_i=1\)

\(p_i\)：成功时查第 \(i\) 项的概率；\(c_i\)：命中它所比较的关键字个数。

本例假设顺序查找折半查找
成功查询，11 个记录等概率63

折半：\(\dfrac{1+2\times2+3\times4+4\times4}{11}=3\)

平均 3 次不表示每次 3 次，也不表示最坏 3 次。顺序成功均值为 \((n+1)/2=6\)。

表长增加，代价怎样增长？

方法最坏比较关键字数这里的条件
顺序基线n不利用有序性提前停止
数组折半\(\lfloor\log_2 n\rfloor+1\)（n≥1）按关键字有序，且能 O(1) 访问中点

本例 n=11：折半最坏为 4，成功 ASL 为 3，含义不同。

折半每轮把候选规模约减半，时间为 O(log n)；空表不比较。

特殊长度的 ASL 闭式公式保留其前提，不用于任意表长。链表节点走访成本需另计。
