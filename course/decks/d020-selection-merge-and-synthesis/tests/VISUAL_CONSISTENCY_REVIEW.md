# D020｜与 D017/D018 课件视觉一致性专项评审（VC-01）

> **状态**：独立评审分支，正式 D020 已于 PR #55 合并。此文档区分实际观察、设计判断、自动验证和后续教师审阅，不以共用 CSS 或自动截图代替实际课堂观察。

## 一、对象与第一性原则

检查对象：D017（BST/AVL）、D018（散列）的**已交付课件**作为课程同类表达参照；D020 作为本次修订对象。D019 的后期反复返修提示我们，需要针对**实际渲染结果**而非文本或 CSS 文件进行一致性复核。

**一致性不是所有页面长得一样**。应统一课程层面的识别、阅读顺序、标题与正文层级、任务提示、答案展开和作业交接；而树、数组、桶及动态轨迹应服从各自算法对象的性质和教学职责，不作像素级强制统一。

归一化比较原则：

- **共有 UI 由公共组件定义**：页眉、导航、课程标题、页脚、页码、大纲与分节页面优先验证公共组件的实际 CSS 属性和播放器状态；不增加 D020 局部覆盖。
- **相同语义的表达保持接近**：比较正文、问题、辅助标注、代码、提示与正式 A/B 作业的视觉等级；建议同类字号差异不超过实际教学意义允许的量，避免通过整体缩字换取“通过”。
- **不同算法的表示允许有差异**：例如 AVL 树旋转与最大堆的树图不可能像素对齐，但节点关键字、下标和关系必须可辨。
- **可验证与实际学习效果分开**：Chrome 三尺寸截图和 CSS 数值证据能够检查显示与交互一致性，不代表学生实际理解或后排可读性已验证。

## 二、压力测试流程与准入标准

| 流程 | 实际动作 | 准入条件 |
| --- | --- | --- |
| VC-F1 主源与版本 | 对 D017/D018/D020 当前 main 的正式 `slides.py`、HTML 与共享工具进行核验 | 不把旧原型或 PR 状态误作当前正式课件 |
| VC-F2 课程共同版式 | 在同一浏览器与三种尺寸下取封面、大纲、首个分节、首个独立任务、最后一页 | 页眉／标题／页脚／播放器字体与位置使用同一共享规则 |
| VC-F3 同语义对照 | 检查 D020 的正文、数组下标、记录 ID、任务提示、答案和代码区 | 层次清晰，关键辅助信息不可显著小于基准；作业页风格与 D017/D018 同类 |
| VC-F4 实际状态与截图 | 通过真实 `#slide-select` 导航，不手动切换 `.active`；测试默认页、展开态与关键动画 | 截图中的标题、选中页、页码一致；原题、结果、记录 ID 不丢失 |
| VC-F5 课件工程回归 | 执行 D020 34 页源契约、动态测试和 1280×720、1440×900、2048×1107 浏览器检查 | 无默认视口溢出、横向裁切、未允许的答案泄露或脚本错误 |
| VC-F6 教师验收 | 选取封面、两种图示、独立任务、动态页与作业页实际投影审阅 | 人工确认后排可读性、视觉节奏、页面认知职责 |

**问题分级：** P0 为遮挡、横向溢出、脚本或导航与实际页面不一致、关键数值/身份不可辨、答案状态错误；P1 为同类文本显著缩小、课程作业视觉结构明显偏离、图示标注偏小；P2 为不影响理解的局部间距/色差。P0 必须清零；P1 必须修订或给出明确保留理由；P2 视实际页面适配处理。

## 三、首轮已证实的差异

| 对象 | 观察证据 | 处置方向 |
| --- | --- | --- |
| 数组下标／记录 ID | D020 原 `.d20-cell small` 字号 `clamp(12px,1.04vw,17px)`，D017 的同类数组辅助标注为 `clamp(16px,1.18vw,19px)` | 改成 D017 标注基线，适度调整记录数值视觉层级，继续检查 720p |
| 任务提示 | D020 原独立任务提示为 `clamp(21px,1.62vw,27px)`，D017 用 `clamp(24px,1.85vw,29px)` | 对齐问题字号，不压缩学生独立作答职责 |
| 作业页 | 实际 1280×720 截图：D017/D018 用直接的 A/B 文字层级与浅色代码区，D020 原来是两张卡片加深色代码区，主要正文也偏小 | 保留同一 A/B 要求与运行命令，使用统一文本主次、浅色代码区和适当留白 |
| 截图可信性 | D020 旧 `check_full.cjs` 用 `.classList.toggle("active")` 直接选择截图页，页眉选择器和页脚仍可指向第 1 页 | 新增专门 QA 脚本，通过共享播放器 `#slide-select` 真正导航并核对页码后截图 |
| 封面结构 | D017/D018 采用单个主问题 + 少量承接说明；D020 原封面为两张解释卡和一个独立高亮长条 | 合并为一个主问题卡，不改变专业问题与学习职责，减少新的版式竞争 |

上述属于**代码与已获取的浏览器截图**支持的初步结论，修订后仍需重新截图确认，不写成已验证修复。

## 四、确定性检查与证据位置

- `tests/check_visual_consistency.cjs`：实际导航 + 三个课程在三个尺寸中的共有视觉属性及 D020 34 页；D020 主页面检查默认溢出、任务答案泄露、KaTeX 错误、数组标注、封面和作业页阅读等级。
- `tests/check_full.cjs`：完整 D020 的页面角色、导航、动态归并/桶状态与答案展开功能。
- `.github/workflows/d020-visual-consistency.yml`：在隔离修订分支运行、归档 1280×720/1440×900 对照截图、`visual-metrics.json` 和 `visual-metrics.tsv`，全部成功后才同步派生 `index.html`。
- 未修改 D017、D018、D019 的任何源码或课程共享 CSS；本轮不改变算法机制、例题期望结果和正式作业的必做/选做范围。

## 五、尚待确认的边界

这轮自动检查即使通过，也只能说明所检条件下的代码、排版与交互满足约束；不等于全部页面在真实教室的投影环境中达到相同的感知质量。最后仍应由教师对照真实截图审阅 1280×720 的文字、树/桶内部标注、动态过程与展开答案的持续可见性。后续发现的问题应以可复现页面 ID、窗口尺寸、状态和预期差异记录，不使用“看起来不统一”作为唯一工程判据。
