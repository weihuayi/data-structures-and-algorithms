## 一、教学中心与专业范围

**主问题**：面对相同排序任务，能否通过维护结构、组合有序序列、利用关键字表示，减少重复工作；不同机制的正确性、代价与适用条件如何判断？

**主要认知跨越**：从对单个排序算法执行步骤的掌握，发展到理解“有效信息—维护／利用机制—正确性—代价—条件化选择”的关系。它不是单纯记忆性能表；不把复杂度阶相同视为工程行为相同。

- **排序契约**：关键字、完整记录与记录身份分离；正确输出满足有序、排列保持、终止；稳定性是可能的附加约束。重复关键字在图示和测试中保留身份。
- **选择排序（8.4）**：简单选择的每轮最小值就位和二次比较代价；树形选择（竞赛树）复用胜者路径信息的机制导航；二叉最大堆的形状与堆序、数组表示、建堆、向下调整、重复取最大值完成升序。
- **归并排序（8.5）**：两个有序子序列的首候选选择、输出前缀不变量；递归分解和线性归并；稳定合并规则；标准数组实现的辅助空间。
- **基数排序（8.6）**：最低位优先（LSD）示例、多关键字次序、链式桶的稳定分配与收集；复杂度必须声明数位数量、基数和每轮分配成本。计数排序作为利用整数取值范围的补充对照，不替代教材的链式基数排序。
- **统一判断**：区分比较排序的决策树下界与关键字受约束时的非比较排序；按时间、额外空间、稳定性、输入特征、范围和任务输出选择算法；Top-k 不等于必须完整排序。

**深度边界**：自底向上建堆 \(\Theta(n)\) 的严格求和、决策树下界完整证明、工程级 in-place merge、生产级基数排序与外部排序败者树／置换选择，作为教师专业支撑或自学导航；不以课堂完成严格证明为达标必要条件。教材 8.4.2 树形选择不能被完全遗漏，8.6 链式分配／收集不能降格为仅展示最终结果。

## 二、先修、输入与正确性约定

- D003/D008：0 起连续数组及完全二叉树形状；\`left(i)=2i+1\`、\`right(i)=2i+2\`（需检查下标是否小于有效堆大小）；D017：BST 全局左右顺序与 AVL 平衡不同于堆的父子堆序；D006：递归与子问题；D019：有序、排列保持、稳定性、插入前缀、快排划分——**只作设计接口，不假定已经实际学会**。
- 主例均以升序排序为目标。二叉最大堆定义：完全二叉树且各父结点关键字不小于孩子；数组的有效堆范围是 \`[0, heapSize)\`，排序后缀是 \`[heapSize,n)\`。相同关键字的调整规则须明确，以免将某一确定轨迹当成唯一合法堆。
- \`siftDown(i,m)\` 的前提：\`i\` 的两个孩子子树已是最大堆；任意无序数组不能仅在根调用一次 \`siftDown\` 就宣称完成建堆。
- 标准稳定归并：左右子序列来自原记录序列连续的左／右范围，且各自已按关键字稳定排序；关键字相等时先取左边。两个来源完全独立且无共同初始次序时，跨来源“稳定”需额外定义。
- LSD 基数排序：对非负整数关键字补足相同位数，低位到高位；每轮在各桶中保持输入顺序，按桶号依次收集。独立的记录 ID 不随移动丢失。
- 成本口径区分比较、记录移动、数组读写、临时存储与真实耗时；常见数组实现的简单选择 \(\Theta(n^2)\) 比较、堆排序最坏 \(\Theta(n\log n)\) 时间及迭代实现 \(O(1)\) 工作空间、标准归并 \(\Theta(n\log n)\) 时间和 \(O(n)\) 辅助存储、LSD 基数 \(O(d(n+b))\) 时间与实现相关空间。树形选择与基数不作无条件优越性主张。

## 三、G1–G4 学习目标及最低证据

| 目标 | 学生的可观察行为 | 独立证据 / 正确性检验 |
| --- | --- | --- |
| **G1 选择与堆的机制** | 比较简单／树形／堆选择的可复用信息；判定并构造最大堆，执行一轮堆顶提取 | P1：新的 5–7 元素输入，给出有效堆前缀、排序后缀和每步调整依据；解释 \`siftDown\` 的前提 |
| **G2 有序结果的归并** | 完成两个有序记录序列的稳定归并，解释每步为何选择当前最小值，以及递归组合为何正确 | P2：新输入、含重复关键字和记录 ID；独立完成下一步、输出前缀与稳定性判断 |
| **G3 代价与非比较边界** | 用机制解释比较次数、额外空间与成立条件；完成链式基数排序的稳定分配／收集，识别比较下界的适用模型 | P3：给出当前数位的桶内记录顺序和收集结果；指出破坏稳定收集会出现什么错误 |
| **G4 条件化选择** | 在新任务中依据时间、空间、稳定性、范围、记录规模和输出要求比较至少两种候选方案 | P4：一个场景改变关键字范围或额外内存约束后，说明方案何以改变；不把某算法说成无条件最好 |

“会按动画推演”不等于能解释；“代码测试通过”不等于学生理解。P1–P4 的输入、提问和答案必须分别可见；展开答案时保留原输入。课件实现、教师审阅、课堂实施、学习达成是四类不同证据。

## 四、主例、反例与阶段任务

| 用途 | 样例及要点 | 必需的核对 |
| --- | --- | --- |
| 堆的教师主例 | \`[9,7,8,4,5,6,3]\` 用于堆序、插入／删除机理；教学可复用树形与数组表示 | 结点下标、形状、堆序同时准确 |
| 堆的 P1 独立任务 | \`[4,1,7,3,6,2,5]\` 自底向上建堆：\`[7,6,5,3,1,2,4]\`，一次提取后 \`[6,4,5,3,1,2 | 7]\` | 每轮顺序固定为 i=2,1,0；说明“构造合法堆”不必只有一个数组答案 |
| 堆前提反例 | \`[2,5,7,3,4,6,8]\` 从根直接下沉可能得 \`[7,5,8,3,4,6,2]\`，仍非合法最大堆 | 标明**无序数组不可直接调用根调整** |
| 归并 P2 | 来自同一原始序列的连续左／右半段：\`L=[2甲,5乙,8戊]\`，\`R=[2丙,6丁,7己]\` | 输出 \`[2甲,2丙,5乙,6丁,7己,8戊]\`；相等取左 |
| 稳定性反例 | 简单选择对 \`[2甲,2乙,1丙]\` 的一次交换可得 \`[1丙,2乙,2甲]\` | 有序但不稳定；不能只看关键字 |
| 基数基础示例 | \`[21,13,12,22]\` 个位 → \`[21,12,22,13]\`；十位 → \`[12,13,21,22]\` | 各桶先进先出顺序不变 |
| 教材基数接口 | \`[321,156,57,46,28,7,331,33,34,63]\`，各关键字补齐三位 | 个／十／百位逐轮**分配、链结、收集**，不只报最终数组 |
| P4 综合选择 | 分别给出“0–100 整数成绩稳定排序”“任意比较键且内存有限”“仅求前 k 大” | 先写数据契约，再选候选算法并给约束，防止机械配对 |

## 五、认知路径与 90 分钟候选预算

30 页候选 Storyboard 的详细页面职责见 [storyboard.md](storyboard.md)。下表的时间属于教学假设，**尚未计时排练**，不把页面数等同于时间，也不把一次正确回答等同于全班理解。

| 阶段 | 目标及页面 | 讲解／互动职责 | 分钟 |
| --- | --- | --- | ---: |
| S0 排序契约与诊断 | 01–03 | 回收 D019 的记录身份和稳定性，不假定其已达成 | 5 |
| S1 选择机制 | 04–05 | 简单选择与树形选择：为什么保存比较结果能减少重复寻找 | 6 |
| S2 堆结构及排序 | 06–14 | 形状、堆序、数组、修复前提、自底向上建堆、P1、排序后缀及代价 | 27 |
| S3 第一阶段检查点 | 15 | 检查堆机制是否真正理解，45 分钟前自然断点 | 4 |
| 机动一 | — | 处理 P1 的典型错误 | 3 |
| **第一段合计** | **01–15** | — | **45** |
| S4 归并机制 | 16–21 | 两个有序后缀、P2、稳定性、不变量、递归与代价 | 18 |
| S5 基数机制 | 22–26 | LSD、桶内顺序、教材链式接口、P3 | 14 |
| S6 比较与判断 | 27–28 | G1–G4 综合与条件变化 P4 | 8 |

| **第二段合计** | **16–30** | — | **45** |

**现实条件**：90 分钟是两段各 45 分钟的有效教学预算；如真实课间从 90 分钟内扣除，必须重新测算。大班独立作答用“30–60 秒独立判断 → 必要同伴讨论 → 教师解释典型错误”，不是安排每人当堂完成完整 C11 编程。若超时，先缩减重复演示、复杂度严格证明与额外例题，不取消 P1/P2/P3 的关键独立判断。备用的 80 分钟方案及时间风险在 [prototypes/REVIEW.md](prototypes/REVIEW.md) 记录。

## 七、表达、工程和验证边界

本阶段只建立 \`README.md\`（教学设计卡）、\`storyboard.md\`（候选页面接续），及 \`prototypes/\` 三页隔离原型；不得提前把原型登记为正式 Deck，不创建 \`slides.py\`，不在 \`course/decks/README.md\` 登记 D020，也不修改 Offering。

隔离原型检验堆下沉的前置条件与错误路径、稳定归并的身份顺序、链式基数桶内先进先出顺序；其真实语义与计算轨迹使用独立 JavaScript 状态生成器和测试，不凭静态图推断正确。**隔离原型不是正式课件共享组件适配的验证证据**；转正式课件后必须使用仓库的 \`CourseDeck/Section/task_workspace\` 及共性检查，再进行 1280×720、1440×900、2048×1107 默认和答案展开的真实浏览器回归。

验收分为：专业数据与状态正确、学习任务与答案完整、视觉与交互可用、时间预算可行、教师审阅、实际课堂反馈。已有的专业推演和机器测试不自动提升后面几类证据的状态。
