# D006 栈与递归：程序执行的栈模型｜学生讲义

## 谁在记住"该回到哪里"

上次课留下的问题：main 调 f、f 调 g，g 返回之后，为什么恰好回到 f 里调用它的下一行？答案不是"恰好"——是系统一直在记着。本次课把这位"记事者"请出来：它就是 D005 讲的栈。

## 函数调用栈：每次调用压一帧

每发生一次函数调用，系统就往内存里压入一个**栈帧**，里面装着三样东西：

- **返回地址**：调用处的下一行；
- **参数**：这次调用收到的输入；
- **局部变量**：这一层自己的草稿纸。

以 main → f → g 为例，栈（上顶下底）依次是 g、f、main 三帧。g 返回时弹掉自己的帧，栈顶正好是 f，于是恰好回到 f 的下一行——**返回时只需看栈顶，不用搜索、不用选择**。

为什么恰好是栈？因为调用与返回的顺序天生是 LIFO：最后开始的调用，必须最先结束——g 不返回，f 无法继续。D005 的栈不是玩具，它是程序每一秒都在跑的机制。

[`code/call_trace.c`](code/call_trace.c) 让 main → f → g 各打印进入、退出一行，缩进就是栈深，并打印各层局部变量的地址：进入顺序 main → f → g，退出顺序完全反过来；三个地址落在同一片相邻区域，但各属一帧、互不相同。先预测、再运行、再检查。

## 如果永远返回不了：stack overflow

调用只进不出，栈帧只压不弹，而栈空间是有限的——耗尽的一刻就是 **stack overflow（栈溢出）**。正式认识这位"老朋友"：以后程序崩在这里，先去找那个永远返回不了的调用。

## 递归：自己给自己压帧

函数调用自己，合法吗？合法，而且机制上毫无特殊：每次调用——不管调的是别人还是自己——都压一帧，每层的参数、局部变量各有一份、互不干扰。**递归 = 自己给自己压帧，同一个栈，同一套规则。**

数学早已递归。阶乘的定义本身就是递归的：

$$n! = n \times (n-1)!, \qquad 0! = 1$$

要算 $n!$，先算 $(n-1)!$——用更小的同类问题定义自己；$0! = 1$ 是出口，定义不能无限退下去。递归定义天然可以翻译成递归程序：

```c
int factorial(int n) {
    if (n == 0) return 1;   /* 出口 */
    return n * factorial(n - 1);
}
```

## factorial(4)：栈的生长与回退

手工推演 factorial(4)：

- **压帧**：main → f(4) → f(3) → f(2) → f(1) → f(0)；
- **回退**：f(0) = 1 → f(1) = 1 → f(2) = 2 → f(3) = 6 → f(4) = 24。

[`code/recursion_demo.c`](code/recursion_demo.c) Part 1 把这条轨迹打印出来（课件里的四行程序加上了打印）：进入 5 行、返回 5 行，返回值逐层 1、1、2、6、24，与手工推演逐项一致。

## 递归三要素

1. **基础情形**：不再递归的出口（$0! = 1$）；
2. **递推步骤**：用更小的同类问题表达自己（$n! = n \times (n-1)!$）；
3. **向基础情形收敛**：每次递归，问题必须真的变小。

缺了基础情形，就会永远压帧、直到栈溢出。三要素不是建议，是生死线。

## 递归信任：只看一层

写 factorial(n) 时，我们假设 factorial(n−1) 已经能给出正确答案——这就是**递归信任**，它与数学归纳法的归纳假设是一对双胞胎：归纳法只验证起点（$n = 0$ 成立）和一步（若 $n-1$ 成立则 $n$ 成立），其余一概不用管。

递归心法：**不要"跟到底"，只看一层**——设计这一层，信任其余层。初学者最大的误区，是试图在脑中展开全部层。

## 程序 vs 执行：回收 D002

程序只有四行，执行时却长出五个栈帧、又逐层弹回。D002 的话在递归上完整兑现：**程序是执行过程的描述，不是执行本身**——同一份代码，被栈展开成任意深的执行。

## 汉诺塔：规则与"把 n−1 个看成整体"

三根柱子 A、B、C，$n$ 个大小不同的盘子起初全在 A 上（大盘在下）。规则：一次只移一个盘子；大盘不能压小盘；全部移到 C。

正面硬想 $n$ 个盘子的每一步，人脑装不下。关键一步是**把上面 $n-1$ 个盘子看成"一个整体"**：

1. 把 $n-1$ 个"整体"从 A 移到 B（C 帮忙）；
2. 最大的盘子从 A 移到 C；
3. 把 $n-1$ 个"整体"从 B 移到 C（A 帮忙）。

第 1、3 步就是更小一号的原问题——递归信任的实战：你只需要设计这一层。

## hanoi(3) 的七步

先推演 2 盘：小盘 A→B，大盘 A→C，小盘 B→C——3 步。展开 3 盘，共 7 步：

1. 盘 1：A→C
2. 盘 2：A→B
3. 盘 1：C→B
4. 盘 3：A→C
5. 盘 1：B→A
6. 盘 2：B→C
7. 盘 1：A→C

第 1–3 步是"2 盘移到 B"，第 4 步最大盘落位，第 5–7 步是"2 盘移回 C"。[`code/recursion_demo.c`](code/recursion_demo.c) Part 2 打印的 7 步与此逐步一致。

## 要挪多少步：指数

设 $T(n)$ 为 $n$ 个盘子的最少步数，按"整体"法：

$$T(n) = 2T(n-1) + 1, \qquad T(1) = 1 \;\Longrightarrow\; T(n) = 2^n - 1$$

递归关系的解是**指数**。64 个盘子的寓言：僧侣昼夜不停、每秒一步，也要五千多亿年——比宇宙的年龄还长得多。每多一个盘子，工作量翻倍。程序可以验证：hanoi(4) = 15 步、hanoi(5) = 31 步，正是 $2^4 - 1$ 与 $2^5 - 1$。

一行回收：Python 课见过的斐波那契递归，慢在**重复计算**（同一子问题算了又算）；汉诺塔慢在**问题本身**（每一步都是必需的移动）——两种不同的慢，递归都没有错。

## 递归的代价与转化（轻处理）

**代价**：每次调用一帧，递归多深、空间就多大；深度失控就是栈溢出。两条退路：

- **尾递归 → 循环**：递归调用是最后一步时可直接改成循环，阶乘的循环版一行就够：`for (r = 1; n > 0; --n) r *= n;`
- **一般递归 → 显式栈**：把系统替你维护的栈，换成自己维护的栈——这个栈，你在 D005 已经会写了。

工具已在手，用到时再展开。

## 什么时候用递归最自然

问题本身有递归结构时，递归不是技巧，是直译。预告三次以上的回收：树的定义就是递归的——"根 + 若干棵子树"（D008/D009）；图的深度优先——走完一条支路、退回再走下一条（D012）；快排与归并——把序列分成更小的同类问题（D019/D020）。

## 回到教材：递归工作栈

教材 3.4 节指出：递归程序的执行借助一个**递归工作栈**——每次递归调用，将返回地址、参数与局部变量压入栈中；返回时依次弹出，恢复上一层的现场。递归工作栈就是本讲的函数调用栈：同一个东西，教材给了名字。教材同时给出递归效率分析的方向：递归层次越深，时间与空间开销越大。

## 本质收口

递归 = 系统替你维护栈。看穿那层替你做事的栈，递归就不再神秘。
