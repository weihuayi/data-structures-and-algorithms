# D006｜栈与递归：程序执行的栈模型

## 本质关系

函数调用栈：每次调用压入一个栈帧（返回地址 + 参数 + 局部变量），返回时弹帧——LIFO 保证最后调用的最先返回，这解释了"g 返回后为什么恰好回到 f 的下一行"。递归 = 系统替你维护栈：函数调用自己在机制上毫无特殊，就是自己给自己压帧，同一个栈、同一套规则。递归三要素（基础情形、递推步骤、向基础情形收敛）与数学归纳法同构（递归信任 ↔ 归纳假设），心法是"不要跟到底，只看一层"。9/14 课堂讨论的"程序是执行过程的描述，不是执行本身"在递归上完整兑现：四行代码被栈展开成任意深的执行。递归的代价（深度即空间）与转化（尾递归 → 循环一句带过；一般递归 → 显式栈，只点明"这个栈 D005 已经会写"）轻处理。

## 接口方向

- **教材锚点**：《数据结构（C语言版）（第3版）》3.4——栈与递归的实现、递归工作栈、递归效率分析。
- **数学接口**：数学归纳法（只验证起点 + 只验证一步）；n! 的递归定义（0! = 1 是出口）；汉诺塔递归关系 T(n) = 2T(n−1) + 1，解为指数 2ⁿ−1。
- **生活连接**：排队问人数——问前面的人"你排第几"，答案加一（第一个人不用问）。
- **计算机接口**：函数调用栈（栈帧、返回地址）；stack overflow 正式介绍为"老朋友"，程序崩在这里要认得。
- **回收 D002**："先预测、再运行、再检查"的课堂口径。
- **回收课堂讨论**："程序是执行过程的描述，不是执行本身"（出自 9/14 课堂口头讨论，不在 D002 课件中）在递归上完整兑现。
- **回收 D004**：链表（课后练习：递归逆序打印链表）。
- **回收 D005**：栈机制（LIFO 正是调用与返回的顺序）；留问"谁在记住该回到哪里"开场回收；显式栈（递归转非递归的工具）；括号匹配（课后挑战：改写成递归）。
- **预留回收**：树的递归定义与遍历（D008/D009）、图的深度优先（D012）、快排与归并（D019/D020）——明确告诉学生这个思想还会用三次以上。

## 主要教学目标

- 能说出栈帧的三样内容，解释 LIFO 如何保证"最后调用的最先返回"；
- 能画出 factorial(4) 的完整栈轨迹（压帧五层，回退 1→1→2→6→24）；
- 能说出递归三要素并检查一段递归缺了哪个，理解缺基础情形 → 栈溢出；
- 能只用"一层"的语言写出 hanoi 的递归步骤（移走整体、落最大盘、移回整体），并由 T(n) = 2T(n−1) + 1 推出 2ⁿ−1；
- 建立"递归 = 系统替你维护栈"的本质理解，知道递归的代价与两条转化退路。

## 主要问题

- 谁在记住"该回到哪里"？每次调用系统压一帧，为什么恰好是栈？
- 如果永远返回不了呢？函数调用自己，合法吗？
- 递归三要素缺哪个会死？递归信任与归纳法是什么关系？
- 汉诺塔怎么把大问题变小？要挪多少步？
- 递归的代价是什么？什么时候用递归最自然？

## 主要案例

**汉诺塔为主案例（已确认）**：规则页（三根柱、3 盘图示）→ "把 n−1 个看成整体"的关键一步 → hanoi(3) 七步手工推演（先 2 盘 3 步）→ T(n) = 2T(n−1) + 1 = 2ⁿ−1 与 64 盘寓言 → 程序核对（3 盘 7 步、4 盘 15 步、5 盘 31 步）。factorial 为递归机制的首例（n! 递归定义 → 四行程序 → 栈轨迹推演）；斐波那契只作一行回收（学生已在 Python 课学过：fib 慢在重复计算，汉诺塔慢在问题本身，两种不同的慢，递归都没有错）。排队问人数为生活类比，与归纳、递归程序三列对照收口。
