第二部分 · 用链接动态保持顺序

什么是二叉搜索树（Binary Search Tree，BST）？

二叉搜索树（Binary Search Tree，BST）的顺序性质：对任一结点，整个左子树所有关键字都小于它，整个右子树都大于它；左右子树递归满足同一条件。

满足顺序性质的主例

中序遍历按“左子树 → 结点 → 右子树”访问。由于BST有全子树顺序性质，中序关键字递增，例如根30的左子树依次是 \(16,20,27\)。

反例：只比较直接孩子并不够

若把左子树中的27改为35，它还合法位于根30左侧吗？

虽然35大于直接父结点20，但35 > 30，违反根30对整棵左子树的要求。

教材亦称二叉排序树；本讲默认关键字互异。

第三部分 · 结构形态与搜索代价

规模n增加，最坏路径会有多长？

普通BST的一次查找或沿路径插入、删除，需要经过的结点数受树高h影响。

结构决定高度h实际遍历沿根到某结点的单条路径
一般工作量O(h)
最坏单支形态h=n，因而最坏O(n)
BST顺序正确 ≠ 树高必为 O(log n)

平均情况需要结合输入顺序和查询分布，不能从较矮的主例直接推出最坏对数保证。

第四部分 · 高度约束与旋转维护

左右子树高度怎样计算？

约定：空树高度为0，单结点高度为1；非空树的高度按最长根到叶路径所含结点层数计算。

从树形观察高度

根30的左子树高2，右子树高1。

自底向上计算

h(v) = 1 + max(h(L), h(R))

结点20两个孩子都是叶子，所以其高度为2。根30整棵树高3。

高度描述结构深度，不是关键字的数值。

第四部分 · 高度约束与旋转维护

什么是 AVL 树的高度平衡条件？

AVL树以 Adelson-Velsky 和 Landis 命名：它是BST，并要求每个结点左右子树高度差的绝对值≤1。

满足约束的例子

根30的左右子树高度为2和1，其余结点也合格。

不满足约束的例子

根30左侧高2、右侧高0，高差为2。

第四部分 · 高度约束与旋转维护

平衡因子 BF 怎样从具体高度算出？

平衡因子（Balance Factor，BF）是结点的左子树高度减去右子树高度。

根30的左右子树

左高2、右高1，因此根30的BF=+1。

由高度建立数值判断

BF(v) = h(L(v)) − h(R(v))

左侧更高：BF > 0

两侧相同：BF = 0

右侧更高：BF < 0

AVL每个结点都需要 BF∈{−1,0,+1}。

第四部分 · 高度约束与旋转维护

根 BF=0 就一定是 AVL 树吗？

检查整棵树的各个结点

左、右主子树都高3，因此根30的BF为0。

只检查根30就够了吗？还应检查哪些内部结点？
核对答案与理由

不能。结点20的左子树高2、右侧空，因此BF(20)=+2；结点40左侧空、右子树高2，因此BF(40)=−2。

根平衡不代表整棵树高度平衡；必须检查所有结点。

第四部分 · 高度约束与旋转维护

中间子树B换了位置，为什么顺序不变？

一般右旋需要保留整个子树A、B、C的关键字范围，并将中间子树B正确重接。

结构约束（整棵子树）

A < y < B < z < C

旋转前 z 为局部根，y 是 z 的左孩子，B 是 y 的右子树。

旋转后 y 为局部根，z 为 y 的右孩子，B 变为 z 的左子树。

对应的最小C11链接调整

Node *y = z->left;
Node *middle = y->right;
y->right = z;
z->left = middle;
fix(z); fix(y);
return y;

调用者还要让旧父链接或根指针指向返回的新局部根y。

第五部分 · 结构选择与学习迁移

数组、BST、AVL究竟应怎样选择？

没有一种结构能在所有查询、更新和存储条件下无条件胜出。

结构查找最坏代价动态更新及维护
有序数组O(log n)（可随机访问的折半查找）插入/删除可能移动O(n)条记录
普通BSTO(h)，最坏O(n)沿路径局部改链接，树形依赖插入顺序
AVL树O(log n)维护高度并在必要时旋转，增加实现复杂度

还需要考虑查询/更新频率、缓存局部性、比较成本、数据分布和工程可靠性。

第五部分 · 结构选择与学习迁移

动态有序查找需要维护哪两类性质？

BST：全子树顺序不变量

整棵左子树 < 当前结点 < 整棵右子树

保证一次比较能确定正确的子树方向，但不强制树高。

AVL：增加逐结点高度约束

每个结点的 |BF(v)| ≤ 1

更新可能暂时失衡，旋转在保序前提下修复约束。

中序有序 ≠ 必然是AVL　　性质正确 ≠ 代价保证
