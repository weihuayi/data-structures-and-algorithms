# D005｜受限的线性结构：栈与队列

## 本质关系

栈与队列 = 给同一个线性表施加两种操作限制：栈限制为同一端插入、删除（LIFO），队列限制为一端进、另一端出（FIFO）。能力可以靠"限制"获得——操作越受限、行为越可预测、越能对顺序做保证；接口越窄、不变量越容易维护（top 恒指向最年轻元素；front 守头、rear 守尾），正确性越好保证。循环队列是"表示 + 工程权衡"的集中体现：取模把数组弯成环（同余的数学接口），判空判满撞车用"牺牲一个单元"或"加一个计数器"两种方案权衡。顺序栈/链栈、顺序队列/循环队列/链队，第三次回收"同一抽象、多种表示"。

## 接口方向

- **教材锚点**：《数据结构（C语言版）（第3版）》3.1–3.3、3.5——栈与队列的定义、顺序栈、链栈、循环队列；3.6 案例思想融入括号匹配推演。
- **生活连接**：餐盘（只从顶上放取）、电梯（先到后走）、撤销（最后做的先撤回）；排队与打印任务（先到先服务）。
- **工程连接**：AGV 任务队列（几千台车的任务按到达顺序派发）、消息缓冲削峰——实践种子点到。
- **数学接口**：栈 = 逆序器（最近未配对者先闭合）；取模 = 同余（"到头就绕回"，时钟是日常的同余）。
- **计算机接口**：函数调用栈预告（"谁在记住该回到哪里"），接 D006 栈与递归。
- **回收 D002**："先预测、再运行、再检查"的课堂口径。
- **回收 D003**：顺序表示（数组 + top 的顺序栈；顺序队列的假满）。
- **回收 D004**：链式表示（链栈栈顶位置判断、链队 front/rear 守两头）；"同一抽象、多种表示"。

## 主要教学目标

- 能说出栈与队列各自的操作限制，解释 LIFO/FIFO 语义如何由限制产生；
- 能用四个操作的栈接口完成括号匹配的手工推演（含"遍历完栈非空即错"）；
- 能解释假满的成因，写出循环队列的取模下标与两种判空判满方案，并完成 N=5 的手工推演；
- 能说出"接口越窄、不变量越容易维护"的理由，建立"限制换语义"的设计观。

## 主要问题

- 这些结构为什么"故意不自由"？只允许在一端存取，得到什么？
- 为什么限制反而有用？栈的接口有多大？
- 顺序队列为什么会假满？怎样把数组弯成环？front == rear 是空还是满？
- 栈 vs 队列，限制各在哪、语义各是什么？

## 主要案例

撤销操作与括号匹配（栈，`({[}]` 手工推演）、排队与 AGV 任务队列（队列）、N=5 循环队列完整推演（假满 → 取模 → 判空判满撞车 → 两种方案）、餐盘/电梯/打印任务（生活类比组）。
