# D005 受限的线性结构：栈与队列｜学生讲义

## 这些结构为什么"故意不自由"

上次课留下的问题：餐盘只从顶上放取，电梯里先到的人后走，编辑器的"撤销"最后做的事最先撤回——它们明明可以随便存取，为什么偏要"故意不自由"？

本次课的答案是一个新思想：不发明新的"住处"，只在操作上做文章。线性表已经学过两种表示（顺序表 D003、链表 D004），栈与队列就是给同一个线性表施加的两种操作限制——**能力可以靠"限制"获得**。

## 栈：只允许在一端存取

**栈（Stack）**：插入、删除只能在同一端进行，这一端叫栈顶。最后压进去的元素，最先弹出来——**后进先出（LIFO）**。

为什么限制反而有用？以撤销为例：撤销的语义是"最后发生的，最先撤回"。栈用一条限制，把这个语义变成了保证——不用检查、不用搜索，pop 弹出的恒是最后发生的那一步。**操作越受限，行为越可预测；行为可预测，才能对顺序做保证。**

## 栈的接口只有四个操作

| 操作 | 作用 |
| --- | --- |
| push | 压栈：栈顶加入一个元素 |
| pop | 弹栈：取走栈顶元素 |
| top | 看一眼栈顶，不取走 |
| isEmpty | 栈空了吗 |

比线性表小得多：没有"按位置取"，没有"插到中间"。接口越窄，越不容易用错。

## 括号匹配：在哪一步配不上

规则：遇到左括号压栈，遇到右括号弹栈核对。以 `({[}]` 为例：

| 字符 | 动作 | 栈（左底右顶） |
| --- | --- | --- |
| `(` | 压栈 | `(` |
| `{` | 压栈 | `( {` |
| `[` | 压栈 | `( { [` |
| `}` | 弹栈核对 | 栈顶是 `[`，与 `}` 配不上 |

第 4 个字符处发现不匹配。再追问一步：如果只有左括号、没有右括号呢？——遍历完栈非空即错。栈在这里是一个**逆序器**：最近未配对的左括号，必须最先被闭合。

## 顺序栈：数组 + top

回收 D003：数组天然有一端是固定的——下标 0 作栈底，栈顶用一个下标 top 标记：

```c
#define MAX 100
int data[MAX];
int top = -1;   /* 空栈 */
```

push 是 `data[++top] = x;`，pop 是 `x = data[top--];`。表示不变量：**top 恒指向"最年轻的元素"**。

## 链栈：栈顶放在链表哪一头

回收 D004：栈也可以用链式表示。先自己答：栈顶放头部还是尾部？**放头部**——头插、头删都是 $O(1)$；放尾部，pop 要先走到倒数第二个结点，是 $O(n)$。表示选择又回来了：同一个栈，数组能做，链表也能做。

## 队列：两头各管一件事

**队列（Queue）**：一端只进（队尾），另一端只出（队头）。最先进队的元素，最先出队——**先进先出（FIFO）**。

为什么先到先服务？一是**公平**：谁先到达，谁先被服务，顺序本身就是规则；二是**缓冲**：生产与消费速度不一致时，队列在中间削峰。工程中的 AGV 任务队列就是这两件事：几千台搬运小车的任务按到达顺序进入队列、依次派发；高峰时任务在队列里排队等待，不至于把调度系统压垮。队列 = 公平 + 缓冲。

## 顺序队列的麻烦：假满

顺序队列 = 数组 + 队头 front + 队尾 rear。dequeue 只是 front 向后走一格，前部的位置空出来了，rear 却一路向后走。N = 5 的数组，交替入队、出队几轮之后：rear 顶到数组末尾，前部空着 3 个位置，新元素却进不来——这就是**假满**。

## 循环队列：把数组弯成环

让下标"到头就绕回"：

$$\text{rear} = (\text{rear} + 1) \bmod N$$

取模的余数永远在 $0$ 到 $N-1$ 之间：走到数组末尾，下一步回到 0。数学接口是同余——模 $N$ 的世界里，$N$ 和 $0$ 是同一个位置；时钟就是日常的同余，$13 \equiv 1 \pmod{12}$。

## 判空判满撞车，与两种方案

空队列时 front == rear；可一直入队，rear 绕一圈追上 front，也是 front == rear——**判空判满撞车了**。两个方案：

- **方案一：牺牲一个单元。**最多装 $N-1$ 个元素；$(\text{rear}+1) \bmod N = \text{front}$ 判满，front == rear 判空。
- **方案二：加一个计数器。**多记一个 count：count == 0 判空，count == N 判满，$N$ 个位置全用上。

少用一个格子，还是多记一个数——工程权衡，没有免费午餐。

## 手工推演：N = 5 的循环队列

采用方案一（最多装 4 个），front、rear 从 0 出发：enqueue A、B、C、D；dequeue 2 个；再 enqueue E、F。

- 入队 A–D：rear 走到 4，$(4+1) \bmod 5 = 0 = \text{front}$，已满；
- 出队 2 个：front 走到 2（A、B 离开）；
- 再入队 E、F：rear 从 4 绕回 0、再到 1。

最终 front = 2，rear = 1，$(1+1) \bmod 5 = 2 = \text{front}$，再次判满——E、F 之后一个也进不来。

## 链队：回收 D004 第三次

队列的链式表示：头出、尾进，需要同时守住两头——front 守头（dequeue = 头删，$O(1)$），rear 守尾（enqueue = 尾插，$O(1)$）。同一个队列抽象，数组、循环数组、链表三种表示。"同一抽象、多种表示"（D003 → D004 → D005），到这里应开始成为条件反射。

## 栈 vs 队列：一眼看清

| | 栈 | 队列 |
| --- | --- | --- |
| 限制在哪 | 同一端插入、删除 | 一端插入，另一端删除 |
| 行为语义 | LIFO：后进先出 | FIFO：先进先出 |
| 不变量 | top 恒指向最年轻的元素 | front 守头、rear 守尾 |
| 典型场景 | 撤销、括号匹配 | 排队、任务派发 |

家族关系：线性表 —（限制：同一端存取）→ 栈；线性表 —（限制：一端进、另一端出）→ 队列。

## 本质收口：限制换语义

拿走了"随便存取"的自由，换来了：**语义**（LIFO 与 FIFO，顺序本身有了保证）、**简单**（接口只有三四个操作，不容易用错）、**可维护**（接口越窄，不变量越容易维护，正确性越好保证）。约束不是损失，是设计。

## 回到教材：操作受限的线性表

教材 3.1 节的定义：

> 栈是限定仅在表尾进行插入或删除操作的线性表；队列是只允许在表的一端进行插入、而在另一端删除元素的线性表。

这正是本讲的全部故事：栈和队列是"操作受限的线性表"——逻辑结构没变，操作集合收窄了。见教材 3.1–3.3、3.5 节；3.6 的案例思想已融入括号匹配的推演。
