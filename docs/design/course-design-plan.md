- **版本**：v0.3
- **状态**：草案

- **形成依据**：2026-09-14 设计方案讨论、D001/D002 开发实践、9/9 与 9/14 两次课堂实录、`kb/structured_understanding_memos/` 相关备忘录、2026-09-14 四视角红队压力测试

## 一、文档定位

本方案统筹《数据结构与算法》整套课件的维护与建设，目标是让后续每个 Deck 的开发成为"在既定框架内做局部创作"，而不是每次从零设计。

明确不在本方案范围内的事项：

- **课后作业**：双层结构（书本习题 + 扩展作业）与作业制度已在 v0.3 确立，规范见 `course/assignments/homework-guide.md`，本方案只维护其设计原则；
- **实践阶段项目**：从团队科研和企业项目中提取、2–3 人一组完成，后续单独设计；
- **考核**：期末笔试 70% + 平时 30%（作业约 10%、考勤约 5%、协作项目约 15%）。

## 二、设计哲学

### 2.1 多头接口：课程概念作为连接枢纽

课程中的基础概念和知识不是终点，而是**多头的"接口"**。每个核心概念（表示、序、栈、树、图、映射……）同时向五个方向接出：

1. **教材术语体系**——学生课后能回到课本，术语与考试有着落；
2. **不同领域的问题与概念**——工程的（AGV、齿轮箱）、物理的、数学的（克莱姆法则、线性空间）、计算机的；
3. **学生的生活与学习**——凑单、外卖、绩点困惑，连接他们的过去、现在与未来；
4. **教师的认知、实践与经验**——企业合作中的"翻译"经历、科研项目（FEALPy、NVH 等）；
5. **实践阶段的综合项目**——理论阶段的案例作为项目种子，在实践阶段再次接通。

通过一门课向学生展示世界关系的丰富性；案例来源于科研项目、企业项目和数学课程本身，刻意区别于 CS 教材的计算机中心案例。

### 2.2 丰富性收口于本质关系

展示丰富关系的同时，每个 Deck 必须收口在**少数本质关系**上（不变量、代价、约束、翻译）——这些是可迁移、可指导生存和发展的关系。判断标准借用结构化理解框架的四判据：真实性、生成性、迁移性、边界可见性。丰富性是展示的世界图景，本质关系是学生可带走的工具。

注意：四判据借自结构化理解 Memo（v0.2 草案，其自身声明尚未完成外部证据综述），在本方案中作为**工作假设**使用，不作为已验证结论；"本质关系可迁移"同样是待检验假设，学期末将以学生实际表现为据回流检验（见 §九）。

### 2.3 双层结构：内容层 + 理念层

课堂实际是双层结构：

- **内容层**：Deck 叙事（案例 → 问题链 → 概念锚定），是课件的主体；D001/D002 的初步课堂观察支持其有效性，但尚待系统性证据（见 §九 学生侧观测回路）；
- **理念层**：元学习方法、第一性原理、辩证法、成长对话（如马斯洛辩论、克莱姆法则反例、"把人看成机器"），是课程最独特的内容，以**教师注记层**承载（见第六节），不固化进叙事主线，由教师现场展开。

### 2.4 目标观

课程目标是**理解目标 + 能力目标**，不以知识为主。知识（教材 8 章的概念体系）是接口的载体；理解（建立原来无关系的两个对象之间的关系）、表达、实践、判断四环是贯穿全程的元方法。分数、绩点是副产品，不是目的。

注意：已公布的考核结构（70% 期末笔试 + 教材习题作业）实际激励的是知识层，与本节目标观存在张力。本方案暂以"目标—评价映射表"作为 v0.3 的处置项（见 §九），在此之前，本节目标观的定位是**课程倡导的价值方向**，其实现依赖课堂与实践环节的引导，而非考核强制。

## 三、课程总体结构：两阶段

| 阶段 | 时间 | 连堂数 | 运行方式 |
|---|---|---|---|
| 理论阶段 | 第 1–10 周 | 20（已用 2） | 教室授课；一次连堂 ≈ 一个 Deck |
| 实践阶段 | 第 11–16 周 | 12 | 机房上课；教师最多讲 1 小节，学生分组综合实践 |

**理论阶段**：用一个 Deck 对应一次连堂，便于备课和节奏控制；讲完教材 8 章的关键概念知识。剩余预算 18 次连堂。

**实践阶段**：对前面课程知识的综合实践过程，可把理论阶段没有讲的高阶内容融合进来。现阶段不过早设计，只约定接口：

- 项目从团队研究和企业项目中提取，2–3 人一组；
- **理论阶段的案例即实践阶段项目的种子**（如迷宫 → AGV 路径、配对 → 数据组织、图论 → 调度类项目），案例在课程中"活"两次；
- 项目库与 Deck 地图中的种子案例需要在理论阶段中期完成对齐（责任与截止点见 §九）；
- 具体节奏（发布、工作坊、答辩）在理论阶段中期启动设计。

1. D013 + D014 压缩为一次"图的优化"（保留 MST 完整手工模拟，最短路径以思想与对照为主，计算训练转习题）；

**密度说明**：D009（遍历+恢复训练）、D013（MST 手工模拟）、D015（关键路径算例）、D017（BST/AVL 旋转）为高密度 Deck，设计卡中必须预留课堂手工推演时间，宁可压缩讲授页数。

## 五、单个 Deck 的设计规范

### 5.1 叙事结构骨架

D001/D002 实践的骨架，作为后续 Deck 的默认模板（允许按主题调整）：

1. **连接引入**：从学生生活或领域案例切入（多头接口的一次接通）；
2. **案例与问题链**：具体案例驱动，页面标题优先用问题形式，沿"对象与信息 → 计算表示 → 条件 → 程序 → 运行检查"链条推进；
3. **概念锚定**：回到教材术语，教材定义用「教材定义」引用块明确锚定，与案例解释分开呈现；
4. **对照表收口**：多栏对照（情境 ↔ 数学 ↔ C 表达、跨案例对比）收束在本质关系上；
5. **课后衔接**：教材导航 + 教材课后练习 + （可选）挑战题 + 学习方法自省。

### 5.2 体例约定

继承仓库根 `AGENTS.md` 的 Deck 生产约定（五件套、构建验证、公开性边界），不重复展开。补充：

- 演示代码用 C11，坚持"先预测、再运行、再检查"的课堂口径；
- 交互组件（迷宫、双指针动画等）沉淀在 `tools/deck/` 共享层，按 Deck 需要声明式启用；
- Deck 之间显式衔接：前一 Deck 留下问题，后一 Deck 回到问题。

### 5.3 设计卡制度

每个 Deck 的 `README.md` 按"**本质关系 + 接口方向**"组织设计卡：这个结构的核心理解贡献是什么，它向哪几个方向接出（教材锚点 / 领域案例 / 生活连接 / 实践种子），再附教学目标、主要问题与维护关系。设计卡是 Deck 开发前与 AI 协作打磨的第一对象，是对 AGENTS.md 中 README 规范的扩展结构（AGENTS.md 的同步修订列入 v0.3 待办）。

## 六、教师注记层（理念层的资产承载）

**定位**：理念层不进入叙事主线，以教师注记承载，教师课堂现场展开。它解决两个问题：理念层有了可演化的资产承载，又不破坏 Deck 叙事骨架的纯净性。

**形态与规范**：

- 关键页面加教师注记，**投影时默认收起，主要由教师点开**；
- 注记内容是**设计过的、可公开的教学注释**（学生课后自行查看课件时点开也有收获）；教师真正的私有备注（考勤处理、个别学生情况等）仍不入库，维持公开性边界；
- 注记内容的两个来源：(a) 备课时预设的理念提示与展开脚本（如克莱姆法则 O(n!) 反例的引导路径）；(b) **课后回填**——课堂验证过的现场发挥在课后沉淀为注记候选（候选清单见附录 B）。

**实现决策**（v0.2 新增）：

- 注记以 `<details class="teacher-note">` 直接嵌入所在页的 `body_html`，**不扩展 `SLIDES` 三元组 schema**，不影响页码与进度逻辑；`<details>` 原生支持展开/收起，无 JavaScript 时仍可工作，`deck.js` 只做可选增强；
- `deck.css` 新增 `.teacher-note` 样式；打印模式与连续阅读模式下的展开行为、按钮位置在 D003 试点时确定，确定后回写本节；
- 学生课后材料以 slides（含可点开的注记）为主；自 v0.21 起各 Deck 不再维护独立 handout（见附录 A）；
- **D003 为注记层试点 Deck**，验证后再把最终格式写入根 AGENTS.md；
- 回填内容的公开性判据：不出现可识别的学生个体，不引用考勤与表现性信息；对话实录型内容改写为教学问题设计，不保留现场口语形态。

**回填节奏**：课堂发挥候选在课后 48 小时内记入附录 B（只记要点，成本最低）；每 4 周集中一次把候选整理入库为正式注记。记录不暂缓，入库可暂缓。

## 七、教材接口机制

课件讲教材没有讲出来的东西（可迁移的思维方式、最佳实践、第一性原理、与实际应用的联系），但不脱离教材：

- 教材托底术语体系与考试内容；课件与教材保持**明确的接口**；
- 每个 Deck 末尾设教材导航页，指明对应的教材章节与阅读要求；
- 课后作业为双层结构：A 书本习题（题号在 Deck 课后页明确给出，对接期末笔试）+ B 扩展作业（案例衍生实践）；AI 使用规范与提交规范见 `course/assignments/homework-guide.md`；
- 学生自学教材的配合方式沿用已实践的做法：思维导图 + 费曼式讲解复习（能不看动画解释、能构造让错误方法失败的输入、能修改程序并解释结果变化）。

作业口径裁决（v0.3 已关闭）：教材习题与案例衍生练习不是二选一，而是分层——A 部分对接考试，B 部分深化理解。D001/D002 周按旧口径布置的作业，在 D001/D002 修订时统一到本结构。

## 九、未决问题与待办

**v0.3 待办**（2026-09-14 压力测试已确认、本次未处置的项）：

1. **目标—评价映射表**：逐条声明每个宣称目标由哪个已存在的考核载体检验；无法检验的（如远迁移能力）降级为"课程倡导的价值观"，或在平时 30% 内设计可操作的观察点；
2. **理念层边界规则**：每次连堂理念层时间预算（建议 ≤15–20 分钟，计入设计卡）；每条注记必须写明服务的本质关系；学期中一次匿名问卷检验学生接受度；
3. **轻处理主题的考试边界**：逐条标注"考到什么程度"并给出习题编号自学路径（见 §四）；
