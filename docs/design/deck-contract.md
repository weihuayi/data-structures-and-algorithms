# 课程课件共性约定

版本：1。适用于本课程的课件建设与修订。目的是减少教师重复制作和学生重新识别表达方式的成本。工程检查、教学审阅和真实学习证据分别记录。

## 入口与职责

- `AGENTS.md` 是协作入口；本文件维护当前共性，修订指南维护方法、情境与反例。
- 每讲 `README.md` 维护教学目标、范围、路径、活动预算和证据接口；`slides.py` 维护表达与页面职责；HTML 由工具生成。
- `tools/deck/` 维护共享实现、样例与检查。新 AI 会话先读本入口链、相关组件说明和本讲设计卡，无需读取全部历史讨论。
- 历史规划与个别课件做法可作参考，不自动成为当前强制规则。个人 Memo 不取代课程约定。遇到冲突要标明对象和依据，按当前任务处理。

## 六方面共性

| 方面 | 必须满足（相应情境触发） | 默认采用 | 按需选择 |
| --- | --- | --- | --- |
| 教学目标与证据 | 明确内容边界、必要先修、关键前提及最低学习证据；关键结论与输入准确 | 少数主要认知跨越、目标与活动对应 | 证明深度、扩展练习与额外证据 |
| 课程连续性 | 术语、编号与表示对应可解释；设计、资产、实际运行和达成证据分开 | 回收必要旧知，说明前后接口 | 跨学科或真实项目延伸 |
| 表达组织 | 当前任务可识别；有关联的部分名称、顺序和归属一致 | 多部分课件用公共大纲与起始页，信息从同一声明生成 | 单任务、短专题可省导航；有理由的紧凑组织 |
| 表示与视觉语言 | 图、表、公式、代码含义对应；不只靠颜色传达语义；必要信息在场 | 基础字号层级、间距、数学渲染与公共模式 | 特殊证明图、对象布局、算法特有状态 |
| 教学交互 | 学生作答所需输入与条件可见，提示与答案可区分；中间状态与完成语义准确 | 手动分步、上一步/下一步/重置，答案默认收起 | 是否交互、微步骤粒度与提示形式 |
| 制作与验证 | 主源唯一、派生物同步；报告对应版本与范围；公开性遵守 AGENTS | 复用公共能力，按改动影响检查，留下可追溯说明 | 新模式和局部扩展，使用后再判断是否公共化 |

“必须满足”包括专业判断事项，不等于全部可自动判断。自动检查不能证明数学正确、认知路径合理或学生已经理解。默认形式的偏离只需在设计卡或 PR 简述教学原因、影响与检查；不得以说明解除正确性、必要输入或公开性要求。

## 公共模式与适用边界

1. 大纲表达阶段、问题和实际页码；活动时间默认留在设计卡。部分数和页数均由认知路径决定，不能从页数换算讲授时间。
2. 部分起始页稳定阶段标识、标题层级、当前问题和展开范围。文字主导为首版默认；特殊图示仍可留在普通内容页，不强迫套入导航组件。
3. 任务工作区将必要输入、提问、提示/答案分开，展开后仍保留输入，打印保留提问、隐藏答案。默认可见标题和图注仍需人工检查，不能泄漏独立题答案。
4. 共用图示与播放器不统一算法概念：DFS 访问、子树完成、Dijkstra 确认分别由算法文字、图例和语义测试解释。

单任务课件可以没有部分声明和大纲。声明多个部分后默认采用大纲；紧凑变体在源码记录一次教学理由。组件支持的参数内变化不要求逐页审批。首版 API、使用方法和可运行样例见 [工具说明](../../tools/deck/README.md#课程公共模式)。

## 检查与证据

| 层次 | 机械检查 | 人工责任 |
| --- | --- | --- |
| 结构 | ID、角色、部分归属、生成导航与源码、构建一致性 | 阶段划分及页面职责是否恰当 |
| 语义 | 已测输入的状态、不变量、结果与程序对照 | 论证、教材术语、边界及案例代表性 |
| 呈现 | 指定尺寸的布局、公式、控件与任务输入可见性 | 局部遮挡、后排可读性、默认可见文字泄漏 |
| 教学 | 记录审阅对象及依据 | 目标、活动、学习证据和实际课堂变化 |

报告分开标识静态通过、默认页面检查、完整操作检查、失败、未完成与人工补查。人工记录不改写机器原始结果。检查器保留正常与故障夹具，不能通过放宽规则或更新基准掩盖失败。

报告记录源、共享依赖、工具版本与覆盖范围。改变共享资源时按影响对象回归；全局资源改变不能排除旧课件。影响分析无法确定时保守扩大范围。

旧课件默认页若发现溢出，可与明确基线提交在同一环境重测。仅相同页面 DOM、相同位置和相同溢出数值可记为既有发现；原始失败报告不改写。新增、加重、页面内容变化以及字体/资源等非布局失败仍阻断。此分类只支持所测布局的回归判断，不表示旧页面可用或完整交互已经通过。

## 渐进接入与维护

- 新课件使用当前公共模式和结构信息。旧课件保持可构建；本轮先接入 D014，D013 作为范例和回归对象，不批量改写其他课件。
- 局部修订检查关联内容，不因尚未迁移而强迫整讲改版；已知缺口应具体记录，受本次改动影响时重新核验。必要输入和正确性问题优先解决。
- CI 先报告，成熟检查再按维护者决定设为合并条件；不默认增加审批人数。AI 审阅不替代教师的教学判断。
- 反馈先判断影响的对象、适用边界与重复性，再决定修复内容、公共能力或检查规则，不把一次意见直接升级为全课程要求。
- 后续观察重复返修、问题定位和审阅成本，以及学生能否识别阶段、找到输入、解释关键步骤。工具自测不作为效率改善或教学效果证明。

实施范围与实测记录见 [实施计划](deck-consistency-plan.md)。
